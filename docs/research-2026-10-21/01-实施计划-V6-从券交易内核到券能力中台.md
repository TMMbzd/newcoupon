## 0. 结论摘要

### 0.1 一句话判断

当前系统是一个**可运行的券交易/算钱/账务内核 + 开放接入底座 + 基础流量治理**；简历写的是**全维度券能力中台**。核心交易/账务链路约 9 成，外围平台能力约 3~4 成。缺口集中在四块：

1. **发放域**：只有单用户领取，缺批量、定向、兑换码、定时、异步、预算闸门；
2. **租户治理**：接入侧强，但缺 RBAC、登录态、沙箱、API 版本演进、契约测试、租户生命周期；
3. **风控**：只有领券 IP 频控和单笔优惠占比上限，缺名单、规则、设备、决策、结算冻结、反作弊；
4. **运维证据**：有指标/限流/熔断/预案，缺 SLO、大盘、MySQL/MQ 演练、备份恢复、容量基线、双实例/追踪。

### 0.2 本计划的路线

**先补发放域（让“平台”成立）→ 再补信任边界（让“多租户可运营”）→ 结算深化（让“财务可用”）→ 风控（让“异常可拦”）→ 稳定性（让“可试点/可面试”）→ 平台补齐与收官。**

### 0.3 五条关键决策（详见 §2 与调研文档）

| # | 决策 | 理由 |
|---|---|---|
| 1 | 发放用 **DB 任务/分片/明细三层 + XXL-JOB 双通道 + RedisScanLock**；RocketMQ 只做唤醒/缓冲（可选），事实源是 DB；不引入 Spring Batch | 业界共同模式是“任务化 + 分片 + 限速 + 两级幂等”；DB 是事实源，MQ 丢消息/重复都能从任务表恢复；离线批处理框架不匹配在线进度/取消/按用户幂等 |
| 2 | 管理面用 **Spring Security 6 + Spring Session Redis + RBAC**：`/api` 与 `/console` 统一进 Security 授权链，旧 `X-Admin-Token` 降级为兼容认证过滤器；开放面 HMAC 原样保留 | 不把三套身份混在一起；不重写已验证的开放面认证链；Session 可强制下线、权限即时生效；`/api` GET 不再裸奔 |
| 3 | API 版本用**路径版本 `/open/v2`**，v1 冻结；契约测试用 **OpenAPI schema 校验 + 黄金样例**，Pact 等有外部消费方 CI 再上 | 与现有 `/open/v1` 前缀一致；单仓库阶段上 Pact Broker 过重 |
| 4 | 风控先做**表驱动结构化规则 + 名单 + 设备端口 + 决策动作 + 结算冻结**，不引入 Drools/ML | 规则少而准、可解释可回放；重引擎会把平台变成不可维护的黑盒 |
| 5 | 稳定性用 **业务 SLI + Prometheus/Grafana + Micrometer Tracing/OTel/OTLP + k6 + mysqldump/binlog + JaCoCo/Trivy** | 全部是业界标准件，单机 WSL2 可跑；不引入 K8s/Nacos/微服务 |

## 2. 调研结论与选型

> 本节是结论摘要；完整对比、业界做法与来源见 [00-调研-六域对标与选型](00-调研-六域对标与选型.md)。分级：**公开事实**（官方文档/工程博客可点开）、**产品规则**（公开规则页）、**推断**（我们的判断）。

### 2.1 发放域：任务表是队列，批处理是“按用户幂等”的循环

**业界共同模式**（vivo、美团、京东、字节、得物、有赞等公开资料）：

- 高并发领券走“同步受理 + 异步落库”，受理结果与最终结果分离，提供三态查询；
- 批量/定向发放用“批次 + 任务/明细 + 分片消费 + 限速 + 重试 + 进度”；
- 预算闸门是营销平台的标准件：总预算/日预算、预占、确认、释放、耗尽告警；
- 兑换码是“一次一码、码即权益”，库中只存哈希、明文只出现一次、核销要防撞库。

**我们的选择**：

- `coupon_grant_task`（批次头）+ `coupon_grant_chunk`（执行/lease）+ `coupon_grant_item`（按用户明细）三层；DB 是事实源；
- chunk 用 `SELECT ... FOR UPDATE SKIP LOCKED` 领取，lease 超时回收；`@XxlJob` 只做时钟/扫描，`@Scheduled` 降级；**RocketMQ 只做唤醒**（消息体 `{taskNo,chunkNo}`），MVP 可先 DB 轮询；
- 单用户发放逻辑抽成 `StockGateService` + `IssueService.issueOne(IssueCommand)`，HTTP 入口与批处理共用；**不复制 ReceiveAppService，也不循环调用 receive**；
- 定时发放 = task `schedule_time`，用 DB `NOW(3)` 判断到期，`misfire_policy` 补跑/跳过；不为每个用户建定时任务；
- 异步单发 = 同一 task/chunk/item，`source=ASYNC`，API 返回任务号，查询接口轮询；
- 兑换码 = `coupon_code_batch` + `coupon_code` + redeem log；Crockford Base32 + 校验位，HMAC-SHA256 存哈希，CAS `ACTIVE→LOCKED→USED`，失败回 ACTIVE；码池 `code_reserved` 守恒；
- 预算 = 激活既有 `coupon_activity`，新增 `coupon_budget_account/reservation/ledger` 三表；按 chunk 预占、按成功确认、按失败/取消释放、reaper 回收僵尸预占；ledger 可回放；
- 发放对账 = task/chunk/item 计数、ledger=account、Redis 已扣=DB 桶行、码池/预算守恒；复用 `stock_drift_log` 告警。

**不选**：Spring Batch（JobRepository/Step 模型面向离线批处理，和在线进度/取消/按用户幂等不匹配）；命令 MQ 当事实源（DB 任务表才是事实源）；Redis 计数器做预算权威（预算必须可对账，DB 台账为准）；Hashids/Sqids 当码安全（只是混淆）。

### 2.2 租户治理：三套信任面分开，RBAC 交给框架

**业界共同模式**：

- 机器面（HMAC/AK-SK）与人工面（账号/会话/RBAC）是两条链，不混用；
- 管理后台用 Session + Redis（可强制下线、权限即时生效），或短时 JWT + 撤销表；
- 开放平台用路径版本（`/v1`、`/v2`）或请求头版本（Stripe `Stripe-Version`、GitHub `X-GitHub-Api-Version`）；
- 契约测试：Pact（消费者驱动）或 OpenAPI schema 校验；单仓库/少消费方时 OpenAPI 足够；
- 沙箱通常用独立 test 模式 key + 独立数据标记，而不是复制一套生产环境。

**我们的选择**：

- **Spring Security 6 + Spring Session Redis**：`/api/**`、`/console/**`、`/tenant/**` 进 Security 授权链；`/open/**` 单独链（HMAC Filter 在前、`permitAll`、stateless）；`/actuator/**` 单独链；
- 旧 `AdminTokenFilter` 改名为 `LegacyAdminTokenAuthenticationFilter`（**只认证、不授权**，不加 `@Component`/`@Order`，由 `SecurityConfig` 手动 `new` 并 `addFilterBefore`），保留一个发布周期；授权用 `authorizeHttpRequests` + `@PreAuthorize`，删除 `BUSINESS_WRITE_PATHS`/`isProtected` 路径白名单；
- RBAC 五表：`admin_user/admin_role/admin_permission/admin_user_role/admin_role_permission`；`admin_user_role.tenant_scope` 可空（空=平台级，非空=只能操作该 appId）；权限码 `resource:action`；服务层 `TenantScope` 强制；
- 登录 JSON + Session + Redis（`RedisIndexedSessionRepository`）+ CSRF Cookie；`DelegatingPasswordEncoder` + `BCryptPasswordEncoder(12)`，Argon2id 作为后续可选（需 BouncyCastle）；失败 5 次/15 分钟锁定；`SpringSessionBackedSessionRegistry` 强制下线；会话只存用户 ID，权限每请求从 DB 重新加载（`AdminAuthorityRefreshFilter`）；
- 脚本长期方案：`admin_api_token`（PAT，SHA-256 存储/scopes/过期/最后使用），共享 `X-Admin-Token` 只作迁移期兼容；
- 租户隔离必须补数据层：`user_coupon.uk_idem` 改为 `(user_id, app_id, idempotent_key)`；`coupon_usage` 加 `app_id`（64 张分表逐表 ALTER + 回填）；`coupon_event` 加 `app_id`；否则 RBAC 只是门禁，不是隔离；
- API 版本：`/open/v1` 冻结（只增不改），破坏性变更开 `/open/v2`；响应加 `X-API-Version`、`Deprecation`（RFC 9745）、`Sunset`（RFC 8594）、`Link`；不做请求头版本（路径在 HMAC canonical 里，天然不可篡改）；
- 契约测试：`springdoc` 生成 OpenAPI 3.0.3 + `swagger-request-validator` 校验 + `openapi-diff` 破坏性变更门禁 + Spectral lint + 黄金样例；Pact 等外部消费方 CI 再上；
- 沙箱：`open_app.environment=PROD|SANDBOX`，独立 `sbx-` appId，同库逻辑隔离，`EnvironmentGuard` 在结算/账单/真实退款/Webhook 等资金边界 `assertProd`，定时任务跳过沙箱，定期清理；不做第二套数据源；
- 租户生命周期：`open_app.lifecycle_status` 独立于 `status`；状态机 `DRAFT→PENDING_REVIEW→SANDBOX_ACTIVE→ACTIVE⇄SUSPENDED→CLOSING→CLOSED→DELETED`；`open_app_lifecycle_event` 留痕；补注销/导出/删除/保留期/`legal_hold`/双人审批（`approval_request`）；财务/审计数据保留、非财务数据按保留期清理；
- 审计查询/导出 + 哈希链校验；`audit_log` 加 `actor_type/actor_id/session_id/approval_id/hash_version`；多实例哈希链用 `audit_chain_head` 单行 `FOR UPDATE` 串行，替代单机 `synchronized`；老记录 v1、新记录 v2，不重算历史链。

**不选**：完整 IAM/SSO/MFA（触发条件：企业统一身份接入）；JWT 无状态（强制下线/权限即时生效更难）；把 `/api` 作为租户产品接入面（租户产品走 `/open`；`/api` 只做平台/管理面，但内部加 `tenant_scope` 防越权）。

### 2.3 结算深化：日账单是会计视图，结算批次是应付视图

**业界共同模式**：

- 券/优惠结算按“主体 + 门店/业务单元 + 周期 + 模板”出账单；
- 结算时点常见“核销即结”“T+N”“售后期结束结”；
- 退款冲回：已结算账单不重开，生成调整批次/负账单；
- 对账差异分类：漏记、重复、金额、主体、时间；自动修复只做安全方向。

**我们的选择**：

- 复用 `coupon_share_detail`/`coupon_refund_detail`；新增 `coupon_settle_party`（主体快照）、`coupon_settle_daily_fact`（gross/refund/net 分列、`usage_count`、`run_id`、`quality_flags`）、`coupon_settle_batch/statement/statement_line/adjustment`、`coupon_settlement_hold`、`coupon_export_job`、`coupon_recon_run/diff`；
- 日事实 = 会计视图（含全部明细）；结算批次/结算单 = 应付视图（扣 hold、按周期/时点生成）；两者可对账；
- 结算周期/时点/方式先做租户级配置：`settle_cycle`、`settle_point`、`after_sale_days`、`holdback_ratio`、`min_settle_amount`、`settle_mode=NET`；默认“T+1 净额账单 + 售后期 holdback”；
- 已确认结算单不可改；跨日/跨月退款进调整单；负账单允许结转，不截断为 0；
- 历史 `__default__`/app 不一致/老式无 items 用 `quality_flags` + `settle_eligible` 标记，真实结算默认排除；
- 导出异步 job + 游标 + 流式；CSV 用 OpenCSV，Excel 用 POI SXSSF/FESOD；UTF-8 BOM、防公式注入、一次性短链、审计；
- 账单任务补 `@XxlJob` + `RedisScanLock`/单实例路由 + 失败指标；`accounting_time` 统一退款归日。

**不选**：支付/打款/发票/税务（外部系统）；完整结算引擎/清分（当前是券侧结算数据）；把日账单直接当结算单；重开历史账单；EasyExcel 作主选（已归档）。

### 2.4 风控：结构化规则先行，设备指纹端口化

**业界共同模式**：

- 分层：入口频控 → 名单 → 设备/行为因子 → 规则决策 → 人工审核 → 结算 hold；
- 规则引擎多用“场景→规则→因子→动作”，识别与处置分离；
- 设备指纹/人机验证通常接商用服务；自建只做端口 + 本地模拟；
- 券平台只能提供券侧证据与约束，订单/支付/物流真实性由外部系统判定。

**我们的选择**：

- 表驱动 + **规则集版本**：`risk_scene/ruleset/rule/factor/rule_factor/action`；规则集不可变，`DRAFT→CANARY→ACTIVE→ARCHIVED`；因子在代码中实现（IP/用户频次、设备关联账号、退款率、优惠占比、预算燃烧、名单命中）；**不引入 Drools**；结构化表达不了再评估 Aviator；
- `risk_list_entry` 黑白灰 + 值 HMAC + 租户盐 + 时效/原因/申诉；Caffeine+Redis，DB 权威；
- **弱设备信号** `WeakDeviceSignalProvider`/`deviceCorrelationId`（UA/canvas/屏幕/时区哈希 + stableClientId，`LOCAL_SIMULATED`）；不叫“真指纹”，不作唯一拒绝证据；商用 SDK 只留端口；
- 决策四态 `PASS/CHALLENGE/REVIEW/REJECT`；`risk_decision_log` 记录因子快照/所有评估规则/规则集版本，支持只读回放；`REVIEW` 允许业务成功但落 `coupon_settlement_hold`；`CHALLENGE` 走人机验证（Phase 2 可接 tianai-captcha）；
- `risk_asset_state` 独立非分片表，不给 64 张 user_coupon/coupon_usage 加风险列；
- **退款场景 REJECT 降级为“退款照做 + 打标/退券挂起/结算调整”**，不能拒绝消费者退款；
- 反作弊信号：退款率、核销率、券占比、同设备/同用户聚集、短时多次退款、预算燃烧；日任务写 `risk_signal`，规则可引用；
- 结算 hold 只挂券侧应付，不冻结用户退款/资金；放行后进下一批；人工复核 + 证据导出；
- 默认规则宽松、总开关默认关、按租户灰度；误杀可回放；低风险 fail-open + 指标，高风险 CHALLENGE/REVIEW。

**不选**：ML 评分（无标签数据）；商用设备指纹作为唯一方案；把订单真实性判断写进券平台；Drools/完整规则引擎（规则少、要可解释可回放）。

### 2.5 稳定性：SLO 先声明，再谈容量

**业界共同模式**：

- SLO/SLI + 错误预算 + 多窗口燃烧率告警（Google SRE）；
- Prometheus + Grafana 大盘；Micrometer Tracing + OTel/OTLP；
- 故障演练用 ToxiProxy/ChaosBlade/docker pause；
- 备份 = 全备 + binlog，恢复到沙箱并核对；
- 容量 = 阶梯加压、拐点、soak、故障注入压测；单机结果只代表形状/下限。

**我们的选择**：

- **业务 SLI**：新增 `coupon_sli_events_total{journey,outcome,reason}` 与 duration histogram，在服务边界按业务码判定 good/bad/excluded；**不用 HTTP 200/`TradeMetrics.failed` 当 SLI**；
- SLO 三条核心链路：领券 99.9%/P99 300ms、试算 99.9%/150ms、核销退款 99.95%/500ms；28 天滚动 + 错误预算 + 14.4/6/1 多窗口燃烧率；单机口径 `coupon_deployment_info` 明确标注；
- Grafana 四张盘：SLO/预算、领券、资金链路、运行时/依赖；标签有界 + MeterFilter 硬防线；
- Tracing：**Micrometer Tracing + OpenTelemetry bridge + OTLP**，后端 Tempo（Grafana）或 Jaeger v2；不在新项目主选 Brave/Zipkin；dev 100%、prod 5~10%；
- 故障演练：ToxiProxy + `docker pause/stop`；Redis/MySQL/MQ 各硬故障 + 网络故障；断言熔断/fail-open/outbox/守恒；`DRILL PASS`；
- 备份：compose 开 binlog；`mysqldump --single-transaction --source-data=2` 同一次 dump `newcoupon+xxl_job`；恢复到沙箱 + Flyway validate + 校验和；RPO/RTO 写清（本地 15/30min，生产 5/60min）；
- 容量：k6 开放模型四场景；阶梯/soak/故障注入；独立 schema/Redis DB/MQ topic；WSL2 同机标注下限；
- 双实例：compose + nginx + readiness/drain + 不同 `WORKER_ID`；Redis pub/sub + 版本 + TTL 缓存失效；审计链 `audit_chain_head`；滚动重启零 5xx；
- CI：构建/测试/覆盖率/依赖扫描四门；JaCoCo + diff-cover、dependency-review/OWASP/Trivy + SBOM；Dockerfile 多阶段；不做 CD 到生产。

**不选**：K8s/Nacos/网关/微服务（单体阶段）；Brave/Zipkin 作为新主链路；自研大盘/追踪；EasyExcel 作导出主选。

### 2.6 前端/管理台

- Vite + React 18 + TypeScript + Ant Design 5（ProComponents 表格/表单）；`openapi-typescript` 从 springdoc 生成类型；Playwright 覆盖主流程；
- 页面分两批：第一批登录/模板/发放/租户/审计；第二批看板/风控/结算/配置/文档；
- 不手写 API 类型、不自研组件库；nginx 托管，compose profile 一键起。

  - `coupon_grant_task`（批次头）：`task_no`（uk）、`app_id`、`template_id`、`grant_type`、`source_type`、`request_id`（uk_app_request）、`total/success/fail/skip/pending`、`status`、`schedule_time`、`rate_limit`、`max_concurrency`、`limit_policy`、`misfire_policy`、`budget_reservation_id`、`approval_id`、`operator`、`version`；
  - `coupon_grant_chunk`（执行单元）：`task_id`、`chunk_no`、`shard_no`、计数、`status`、`lease_owner/lease_until`、`attempt`、`next_retry_at`；uk `(task_id, chunk_no)`；idx `(status, next_retry_at)`；
  - `coupon_grant_item`（按用户明细）：`task_id`、`chunk_no`、`user_id`、`seq`、`status`、`user_coupon_id`、`fail_code/msg`、`attempt`；uk `(user_id, task_id, seq)`；idx `(task_id, chunk_no, status)`。
  - **item 先单表**；>10M 行或需要按用户查询时再按 `user_id%64` 分片（分片唯一键必须含 user_id）。
- API（开放面，`@OpenResource("grant/task")`）：
  - `POST /open/v1/grant/tasks`：模板、内联 userIds（MVP ≤10,000）/CSV 文件、`grantType`、`scheduleTime`、`rateLimit`、`limitPolicy`；
  - `GET /open/v1/grant/tasks/{taskNo}`：total/success/fail/skip/pending/percent/currentRate/ETA；
  - `POST /open/v1/grant/tasks/{taskNo}/cancel`（`CANCELING→CANCELED` 异步）；
  - `POST /open/v1/grant/tasks/{taskNo}/retry-failed`；
  - `GET /open/v1/grant/tasks/{taskNo}/failures`（CSV）。
- worker：`@XxlJob("couponGrantTaskJob")` + `@Scheduled` + `RedisScanLock`；`SELECT ... FOR UPDATE SKIP LOCKED` 领取 chunk；lease 超时回收；按任务 qps 限速；瞬时错误退避，永久错误 FAILED；独立线程池/连接池，线上 P99 升高时暂停批量。
- **RocketMQ 可选唤醒**：MVP 先用 DB 轮询 + SKIP LOCKED；压测证明需要再加 `{taskNo, chunkNo}` 唤醒消息，事实源仍是 DB。
- 测试：1 万任务恰好发 1 万张；重复 requestId 只建一个任务；重复 chunk/消息不重发；批量+线上领券抢最后 100 张成功数恰好 100；取消后计数守恒；失败重试；崩溃 lease 回收。

#### 1B 定时/异步/兑换码（1.5 会话）

- 定时：task `schedule_time`；`couponGrantTaskJob` 用 **DB `NOW(3)`** 判断到期，`misfire_policy` 补跑/跳过；不提前发；周期任务可选 `(schedule_no, fire_time)` 唯一。
- 异步单发：`POST /open/v1/coupons/issue/async` + `GET .../tasks/{requestId}`；`source=ASYNC`，复用同一 task/chunk/item。
- 兑换码：
  - `coupon_code_batch` + `coupon_code` + `coupon_code_redeem_log`；
  - Crockford Base32（去 I/L/O/U）+ 校验位；手工码 16 位（约 80 bit）+ 限流，二维码 26 位（约 130 bit）；
  - `code_hash = HMAC-SHA256(pepper, normalized_code)`，不存明文；日志/审计只打 mask；
  - `POST /open/v1/codes/redeem`：码 CAS `ACTIVE→LOCKED→USED`，失败回 ACTIVE；崩溃恢复按 request 查 user_coupon 幂等键；统一错误文案防枚举；IP/用户/码限流；CSV 导出加 BOM + 防公式注入 + 一次性下载。
- 测试：定时到点/补跑/重复触发；异步成功/失败/查询；10 万码唯一；1,000 并发兑同一码只成功 1 次；枚举 1 万次 0 成功且被限流；导出只出现一次。

#### 1C 预算账本与发放对账（2.5 会话）

  - `coupon_budget_reservation`：`reserve_no/account_id/biz_type/biz_id/amount/confirmed/released/status/expire_time`；chunk 级预占。
  - `coupon_budget_ledger`：只追加的 RESERVE/CONFIRM/RELEASE/ADJUST 流水。
- 单张成本：满减/无门槛=`face_value`，折扣=`discount_cap`；写进 `coupon_template.budget_unit_cost`；共享预算按 `budget_ratio` 拆平台/商家（MVP 先活动级单账户）。
- `BudgetService`：`reserve`（条件 UPDATE，0 行=`BUDGET_EXHAUSTED`）、`confirm`（reserved→consumed，差额释放）、`release`、`adjust`；chunk 级预占；僵尸预占 `expire_time` + reaper。
- 接入：预算预占在库存闸门之前；库存失败释放；发券成功回填 `user_coupon_id`；核销/退款按 `user_coupon_id` confirm/adjust；退券回可用重新预占，作废/过期释放。
- 对账：`reserved+consumed <= total`；ledger=account；task 计数=item 状态；Redis 已扣=DB 桶行；码池 `allocated + code_reserved <= total_count`；差异落 `stock_drift_log` 告警。
- 指标：`coupon_budget_available`、`coupon_budget_rejected_total{reason}`、`coupon_grant_tasks{status}`。
- 测试：并发 chunk 不超预算；预算耗尽被拦；confirm/release；批量部分失败；退款调整；僵尸预占回收；对账差额。

### 阶段 2：信任边界与租户治理（8 会话）

**目标**：让“多租户可运营、可审计、可接新产品”；对应简历“生命周期/RBAC/API 版本/沙箱/契约测试”。

#### 2A Spring Security 6 + RBAC + 租户隔离（3 会话）

- 依赖：`spring-boot-starter-security`、`spring-session-data-redis`；
- 三条 Security 链：`/open/**`（permitAll、stateless，HMAC Filter 在前）、`/api/**` + `/console/**` + `/tenant/**`（Session/旧令牌）、`/actuator/**`（独立链，health 公开、其余 `ROLE_ACTUATOR`）；**Actuator 必须单独配**，否则自定义 Security 后自动配置退让会裸奔；
- 旧 `AdminTokenFilter` 改为 `LegacyAdminTokenAuthenticationFilter`：只认证、不授权，不加 `@Component`/`@Order`（防 Boot 自动注册两次），由 `SecurityConfig` 手动 `new` 并 `addFilterBefore`；保留一个发布周期，统计使用量后删除；
- 授权：`authorizeHttpRequests` 粗粒度 + `@PreAuthorize` 细粒度；删除 `BUSINESS_WRITE_PATHS`/`isProtected` 路径白名单；`/api` GET 全部要求认证（破坏性变更，公告 + 更新脚本 + `P2cAdminAuthTest`/`AdminSurfaceProtectionTest`）；
- 表（V27）：`admin_user/admin_role/admin_permission/admin_user_role/admin_role_permission`；`admin_user_role.tenant_scope` 可空（空=平台级，非空=只能操作该 appId）；可选 `admin_api_token`（PAT，SHA-256/scopes/过期/最后使用）；
- 权限码：`template:read/write/approve`、`issuance:read/write`、`budget:read/write`、`settlement:read/write`、`risk:read/write`、`tenant:lifecycle`、`app:*`、`audit:read/export`、`config:write`、`plan:apply`、`session:revoke`；
- 角色种子：`PLATFORM_ADMIN/PLATFORM_OPERATOR/PLATFORM_APPROVER/PLATFORM_AUDITOR`、`TENANT_ADMIN/TENANT_VIEWER`；不按页面建角色；
- 登录：JSON `/console/api/auth/login`、`/logout`、`/me`；`RedisIndexedSessionRepository` + `SpringSessionBackedSessionRegistry`；CSRF Cookie（SPA）；`DelegatingPasswordEncoder` + `BCrypt(12)`（Argon2id 可选）；失败 5 次/15 分钟锁定；空闲 30 分钟/绝对 8 小时；登录后轮换 session id；强制下线；
- 权限即时生效：会话只存 `AdminPrincipal(userId, username)`；`AdminAuthorityRefreshFilter` 每请求从 DB 重新加载权限；角色变更/停用/改密触发删会话 + `auth_version`；
- `TenantScope`/`CallerContext`：区分 `TENANT`/`PLATFORM_USER`/`SYSTEM`；租户用户只能访问 `tenant_scope` 内 appId；不是把 appId 映射成角色；
- **数据层隔离**（V27）：`user_coupon.uk_idem` 改为 `(user_id, app_id, idempotent_key)`（64 张分表逐表 DROP/ADD）；`coupon_usage` 加 `app_id` + 索引（64 张分表逐表 ALTER + 按分片回填）；`coupon_event` 加 `app_id`；**不再用 appId 前缀拼进 64 字符幂等键**（会截断/冲突）；
- 测试：认证链矩阵（HMAC 调 `/api` 401/403、session 调 `/open` 6001/6010、旧令牌调 `/open` 无效）、角色矩阵、越权拒绝、CSRF、锁定/解锁、强制下线、权限变更即时生效、跨租户同 userId+requestId 不冲突。

#### 2B 租户生命周期 + 沙箱 + API 版本 + 契约测试（2 会话）

### 阶段 3：结算深化（5 会话）

**目标**：让财务能按“主体 + 门店/业务单元 + 周期 + 模板”拿到可对账、可导出的结算数据；对应简历“结算与财务查询”。

#### 3A 门店/BU + 结算主体快照 + 质量标记（1.5 会话）

- `CalculateRequest`/`ConfirmRequest` 订单行加可选 `storeId`/`businessUnitId`（≤64 字符，默认 `__default__`）；分账/退款复制；`pricingId` 快照冻结。
- 新增 `coupon_settle_party` 主数据快照：`party_type/parent_party_id/display_name/status/source_system/source_version/data_quality`；只存主体 ID/名称/层级/状态，不存完整银行卡/身份证/KYC。
- `coupon_share_detail`/`coupon_refund_detail` 加 `store_id/business_unit_id/quality_flags`；`quality_flags` 位掩码（LEGACY_DEFAULT/APP_MISMATCH/NO_ITEMS/FUNDING_UNKNOWN/ORPHAN_TEMPLATE/NEGATIVE_ADJUSTMENT/MANUAL）；`settle_eligible=0` 不进真实结算。
- `coupon_settle_party_daily_bill` 加 `store_id/business_unit_id/currency`，**先删旧唯一键 `uk_date_app_party_tpl`，再建新唯一键** `(bill_date, app_id, settle_party_id, store_id, business_unit_id, template_id, currency)`；旧行默认 `__default__`；迁移前做数据量/冲突预检。
- 测试：一单两门店、主体/门店/模板交叉汇总、退款回原门店、旧调用方默认、质量标记排除。

#### 3B 日事实 + 结算批次/结算单（2 会话）

- 新增 `coupon_settle_daily_fact`：日期+appId+主体+门店/BU+模板+币种；**gross/refund/net 分列**；`confirm_count`（分账行数）与 `usage_count`（distinct usage_no）分开；带 `run_id/source_max_id/generated_at`；重跑删除/替换本次 run 旧行，不能只 upsert。
- 新增 `coupon_settle_batch` + `coupon_settle_statement` + `coupon_settle_statement_line`；状态 `DRAFT→CALCULATING→CALCULATED→PENDING_CONFIRM→CONFIRMED→CLOSED`，另 `VOID/SUPERSEDED/ADJUSTED`；确认后金额/行/主体/期间冻结，只能新版本/调整单。
- 配置：`settle_cycle`（T+1/T+N/WEEKLY/MONTHLY/MANUAL）、`settle_point`（CONFIRM/AFTER_SALE_END）、`after_sale_days`、`holdback_ratio`、`min_settle_amount`、`settle_mode=NET`；默认“T+1 净额账单 + 售后期 holdback”。
- 生成：按 appId+主体+周期汇总日事实，扣 hold，生成批次/结算单；唯一键幂等；`batch_no/statement_no` 确定性生成；DRAFT 可重跑，CONFIRMED 不可改。
- 测试：批次合计=日事实、结算单头=行、hold 排除、放行进下一批、重跑幂等、确认后拒绝修改、负账单结转。

#### 3C 调整单 + hold + 导出 + 对账（1 会话）

- `coupon_settle_adjustment`：跨日/跨月退款、负账单；`refund_no + original_statement_no` 唯一；已确认单不动，下一期调整。
- `coupon_settlement_hold`（阶段 4 接入风控）：券侧应付 hold，不冻结用户退款/资金；`payable = discount - hold`；释放/作废走下一期调整。
- `coupon_export_job`：异步任务 + 游标分批 + 流式写；CSV 用 OpenCSV，Excel 用 POI SXSSF/FESOD（EasyExcel 已归档，不主选）；UTF-8 BOM、防 CSV 公式注入、一次性短链、权限 + 审计、文件 SHA-256。
- `coupon_recon_run` + `coupon_recon_diff`：券侧内部恒等式全做（行/单券/退款/主体=模板/单头=行/批次=单）；订单侧有数据再做；支付/财务外部。差异分类 + 自动修复只修派生/精确重复，已确认单/主体/外部差异人工。
- `accounting_time` 统一为退款明细 create_time，保留 `original_bill_date`；跨午夜/跨月归属文档化。
- 测试：跨日/跨月退款、负账单、hold 放行、导出 10 万行不 OOM、公式注入、权限、对账差异分类。

#### 3D 账单任务治理（0.5 会话）

- `DailyBillService` 补 `@XxlJob("couponDailyBillJob")` + `RedisScanLock`/单实例路由 + `coupon_bill_job_total{result}` + 失败告警；
- 历史质量回填 + 预检；`__default__`/app 不一致/老式无 items 的结算排除；
- 测试：任务锁/失败指标、质量回填、排除规则、跨日调整。

**阶段 3 验收**：财务可按主体/门店/BU/模板/周期查结算单并导出；批次=结算单=日事实可对账；hold/调整/负账单/历史质量边界清晰；账单任务有锁/指标/告警。

### 阶段 4：风控与反作弊（6 会话）

## 7. 风险、边界与止损

### 7.1 明确不做（当前阶段）

- 活动编排、人群圈选、页面搭建、投放、触达（租户/外部系统）；
- 支付、打款、发票、税务、商家入驻、门店主数据（外部系统）；
- 完整 IAM/SSO/MFA、WAF/DDoS、等保（触发条件：真实企业接入/合规要求）；
- 微服务拆分、Nacos/网关/K8s/多地域（触发条件：团队/流量/部署要求）；
- 物理多库、跨库强一致（当前 1 物理库 ×64 表路由够用；触发条件：单库容量/写入瓶颈）；
- ML 风控评分（触发条件：有标签数据与误杀分析）；
- Drools/Flowable/Seata/TCC/Redisson/Kafka/Elasticsearch（各有替代；触发条件见调研文档）；
- 万能规则引擎、任意表达式（会把平台变成不可维护的黑盒）。

### 7.2 触发条件（写死，避免“以后再说”）

| 能力 | 触发条件 |
|---|---|
| 物理扩库/多库 | 单物理库 > 1TB 或写 QPS > 5,000 持续一周 |
| 微服务/网关/K8s | 团队 > 10 人或多语言服务 > 3 个 |
| 完整 IAM/SSO | 企业统一身份/审计合规要求 |
| Pact | 外部消费方要求消费者驱动契约并进 CI |
| Drools/表达式引擎 | 结构化规则无法表达且规则数 > 50 |
| 商用设备指纹 | 有采购合同/准确率要求 |
| ML 风控 | 有标注数据且规则误杀率不可接受 |
| XtraBackup | 数据量 > 100GB 或要求热备 |
| 物理沙箱 | 合规要求生产/测试物理隔离 |

### 7.3 主要风险与对策

| 风险 | 对策 |
|---|---|
| 发放任务/分片表成为热点/瓶颈 | task/chunk/item 先单表 + 索引；按 task/chunk 查询；>10M 行再评估 item 按 user_id 分片；worker 限速 |
| 预算预占与库存/发券不一致 | 预占在库存前；失败必 release；ledger + reservation + reaper + 对账；chunk 预占 |
| 改 `StockGateService`/`issueOne` 影响老领券 | 先抽方法 + 全量回归；HTTP 行为不变；开关灰度 |
| Spring Security 与现有过滤器冲突 | 三条链隔离 `/open`、`/api`+`/console`、`/actuator`；旧 token 只认证、不加 `@Component`；迁移测试矩阵 |
| L73 64 表 DDL 风险 | 低峰在线 DDL/pt-osc；先备份；校验无重复；先补 `coupon_usage.app_id` 再注销/导出；全链路回归 |
| 审计哈希链多实例分叉 | `audit_chain_head` 行锁/分链；`hash_version`；并发写链测试；动钱审计同事务/outbox |
| 多实例缓存 | Redis pub/sub + 版本号 + TTL 兜底；事务提交后发布；双实例测试 |
| 结算口径跨日/跨月/负账单 | 日事实 gross/refund/net；`accounting_time`；已确认单走调整；负值结转不截断；手工核算 + 测试 |
| 风控误杀/退款合规 | 默认宽松、规则可回放、hold 可放行；退款场景 REJECT 降级；攻击脚本只作验收 |
| SLO 建立在伪成功上 | 先补 `coupon_sli_events_total` 业务码分类；不用 HTTP 200/`TradeMetrics.failed` 当 SLI |
| WSL 内存不足 | observability profile 串行；压测停 Grafana/Tempo/XXL/IDE；`.wslconfig` 限制；`docker stats` |
| 备份恢复不可用 | compose 开 binlog；同一次 dump `newcoupon+xxl_job`；恢复到沙箱 + Flyway validate + 校验和；实测 RPO/RTO |
| 测试变慢/假红 | 共享容器；新集成测试控制上下文数量；全量 `mvn clean test`；不随意改已知偶发断言 |
| 范围蔓延 | 每阶段“明确不做”清单；触发条件表；阶段出口验收 |
