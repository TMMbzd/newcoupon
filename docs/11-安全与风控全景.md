## 1. 第 1 层：业务风控（反作弊）

### 1.1 大厂完整做法（三段式）

**事前拦截**：
- **名单**：黑名单（已确认的坏人：设备号/账号/IP 三库）、灰名单（可疑，加强验证）、白名单（可信，免验证）；
- **频控**：多维度速率限制——同 IP 每分钟 N 次、同设备每分钟 N 次、同账号每分钟 N 次、同"设备+IP"组合——任一超限即拒绝或升级验证。这是成本最低、见效最快的一道；
- **人机识别**：滑块/点选验证码、行为特征（鼠标轨迹/打字节奏——真人有抖动，脚本没有）、JS 挑战（无头浏览器过不去的环境检测）；
- **设备指纹**：采集浏览器/设备特征（canvas 渲染、字体、传感器）生成稳定设备 ID——一台设备换 100 个账号也认得出。这是打"团伙"的根基（单账号维度永远看不出团伙）。

**事中研判**：实时规则引擎/模型——"同设备 5 分钟 3 个账号领同一券"“新注册账号 10 秒内领券”"收货地址聚集"——规则（可解释、可运营）起步，模型（无监督聚类找异常团伙）进阶。判定走独立风控平台，券系统同步调用问"这个人这笔能不能过"。

**事后处置**：**拦截永远有漏网的，回收是最后一道**——异常券批量作废（INVALIDATE）、核销拦截（风控名单用户核销挂起人工审）、封号、追损（法律途径）。没有事后处置的风控是半成品。

### 1.2 我们的状态

| 项 | 状态 | 说明/挂点 |
|---|---|---|
| 频控（IP/设备维度） | ✅ **本批落地**（§6） | 固定窗口 Redis 计数，最小版 |

## 2. 第 2 层：应用安全（AppSec）

### 2.1 大厂完整做法

- **鉴权认证**：C 端登录态（session/JWT——"你是谁"）；B 端调用方认证：**HMAC 签名+时间戳+nonce**（"消息没被篡改、不是重放的"——签名覆盖请求体+时间戳，5 分钟窗口外的拒收，nonce 防窗口内重放）；
- **越权（IDOR）**：水平越权（改 id 看别人资源——防法：每个查询绑定当前身份，`WHERE id=? AND user_id=?`）；垂直越权（普通用户调管理接口——防法：管理面独立鉴权+网关白名单）；
- **注入**：SQL 注入（参数化查询——MyBatis `#{}` 全覆盖）；XSS/CSRF（有前端后的模板转义+token）；
- **依赖漏洞**：OWASP Dependency-Check 进 CI（Log4j 事件的行业教训：第三方库的已知 CVE 自动拦截）；
- **安全测试**：越权/重放/签名失效/未授权访问的**清单化用例集**（不是"测过"两个字，是工件）；上线前渗透测试（内部红队或外采）。

## 3. 第 3 层：数据安全

### 3.1 大厂完整做法

- **密钥管理**：密码/密钥不出库（Vault/KMS 或至少环境变量+加密配置），轮换周期，最小权限（应用只拿到它需要的凭据）；
- **脱敏**：敏感字段（手机号/身份证/卡号）展示与日志双脱敏（`138****1234`），数据库层加密（重要字段列加密或透明加密）；
- **传输加密**：全站 TLS；内网服务间 mTLS（零信任形态）；
- **备份与恢复**：定期备份+**恢复演练**（备份不等于可恢复——不演练的备份是心理安慰）；
- **审计留痕**：谁在什么时候改了什么（操作日志不可篡改），出了事能追责——管理操作全量审计。

## 6. 当前批次落地：领取入口 IP 频控（风控前置最小版）

> 设计裁决记录（2026-09-16，用户裁定"先做必须且重要的"）。

**为什么是它**：五层中唯一"必须且重要且现在就该有"的代码级防护——其余要么已有（越权/参数化/幂等），要么是 M2/M6 的基础设施项。频控挡的是**最高频的攻击形态**（脚本无脑高频领券），且是三段式风控里唯一不需要平台 team 的。

**设计**：

- 组件 `IpRateGate`（infrastructure/risk）：固定窗口计数——`INCR c:risk:ip:{ip}:{窗口起始}` + `EXPIRE`，超过阈值拒绝。固定窗口而非滑动窗口/令牌桶的取舍：实现 5 行、精度足够（阈值边界最多放行 2 倍瞬时——对"挡脚本"这个目标无差）；
- 接线 `RiskControlFilter`（infrastructure/web）：只拦 `POST /receive`（领券是攻击面，建券/查询暂不设防——刻意：频控有误伤成本，按攻击面配）；IP 提取顺序 `X-Forwarded-For` 首跳 → `X-Real-IP` → `remoteAddr`（生产 Nginx 前置时代理头为准——TLS 终结也在 Nginx）；
- 拒绝形态：HTTP 429 + 新错误码域 **7xxx（风控域）**：`RISK_REJECTED(7001)`——与业务 3xxx/4xxx 分开，监控能单独统计风控命中率（风控指标本身是 M2 大盘的一个盘面）；
- 配置：`coupon.risk.ip-rate.{enabled,window-seconds,max-per-window}`（默认开/60s/30 次——正常用户 1 分钟领 30 次不可能，脚本秒破）；测试可关（集成测试直调 service 层不经 HTTP，天然不受影响）；
- **诚实边界**：①单 IP 维度，NAT 出口（公司/校园网共享 IP）会误伤——阈值留了余量+可配置，真实流量下按命中率调参；②不防分布式代理池攻击（那需要设备指纹/行为分析——⛔ 项的触发条件正是这个）；③不做设备维度（无指纹采集端）——`X-Device-Id` 头透传位已留，M6 人机识别时接上。

**测试**：`IpRateGateIntegrationTest`（真 Redis）——阈值内放行、超阈拒绝、窗口翻转恢复、enabled=false 旁路。
