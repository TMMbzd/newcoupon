## 1. 总则

### 1.1 机制与政策分离

- **内核保证机制**：怎么算、怎么锁、怎么核、怎么退、怎么记账、怎么审计、怎么隔离；
- **产品决定政策**：发什么券、门槛多少、发给谁、什么时候发、怎么营销、怎么结算；
- **产品配错政策，内核按配置执行**：产品把“满 0 减 100”配上，内核会按这个规则算；政策合理性由产品和运营负责。

### 1.2 租户与结算主体

- 租户 = `appId`，是数据隔离、配额、配置、审计的边界；
- 结算主体 = 优惠最终算到谁头上、平台和谁结算；可以是商家、门店、经销商、业务单元，也可以就是租户自己；
- **出资方与结算主体是两个维度**：出资方回答“成本谁承担”（平台/非平台/共担），结算主体回答“平台和谁结算”；平台出资 10、商家结算时，成本是平台 10、平台应付商家 10，不能只看“商家承担 0”；
- 结算主体是**可选维度**；没有细分主体的产品落 `__default__` 桶；
- 商家出资/共担券在“有结算主体”的租户里必须绑定主体，避免 A 的券扣 B 的钱。

### 1.3 契约面

| 面 | 内容 | 详见 |
|---|---|---|
| API 面 | 建模板、发券、试算、锁/核销/释放/退款、查询 | 03 |
| 事件面 | 券发放/锁定/核销/退款/过期等事件与 Webhook | 03 |
| 配置面 | 券类型、范围、叠加、出资、限领、退款政策 | 本文 §4 + 03 |
| 扩展面 | 资格、范围、定价、出资、结算、通知 | 本文 §5 + 04 |

### 1.4 契约适用面

`/open/v1` 和 `/api` 不是同一类接入面：

| 能力 | `/open/v1`（产品接入） | `/api`（平台运营面） |
|---|---|---|
| 应用身份 | appId + HMAC + 时间窗 + nonce | 无 appId；单令牌/白名单 |
| 租户隔离 | ✅ 按 appId 隔离 | ❌ 不构成多租户隔离 |
| 写接口 `X-Client-Token` 幂等 | ✅（Redis 可用时；故障时 fail-open） | ❌ 不校验 token |
| 金额/状态/退款/审计 | ✅ | ✅ 同一套业务代码，但调用方必须是可信平台操作 |
| 适用场景 | 多产品、多租户、外部企业 | 平台自己的运营/运维动作 |

**结论**：需要数据隔离、配额、审计、结算边界的产品，一律走 `/open/v1`；`/api` 不作为多产品接入面。

## 2. 能力原语

> 原语 = 内核提供的最小能力单元；产品用这些原语组合自己的业务流程。

| # | 原语 | 做什么 | 关键输入/输出 | 幂等 | 状态 |
|---|---|---|---|---|---|
| 1 | 建模板 / 发布 / 查询 | 定义一类券并发布 | 模板配置 → 模板 ID/状态 | 建模板/查询可用 `X-Client-Token` 回放；**发布不是业务幂等**：重复发布返回 2003/4002，只有同 token 重放被缓存 | ✅ |
| 2 | 发券（领取/批量/定向） | 把券发给用户 | 模板、用户、数量 → 用户券 ID/结果 | 领取用 `X-Client-Token`/requestId；批量按批次号（目标） | ✅ 领取；○ 批量/定向 |
| 3 | 试算（calculate） | 下单前算可用券、优惠、分摊 | 用户、商品行、券列表、`orderNo` → 优惠/分摊/不可用原因/`pricingId` | 默认只读；带 `orderNo` 且开关开启时写/复用快照（同摘要） | ✅ `pricingId` 已实施（灰度默认关） |
| 4 | 锁券（lock） | 下单时占用券 | 订单号、用户、券、可选 `pricingId` → `usageNo` | 业务键 `(orderNo,couponId)`；`usageNo` 由服务端生成；带 ID 时同事务绑定快照 | ✅ |
| 5 | 核销（confirm） | 支付成功后记账 | `usageNo`、商品行/金额/`pricingId` → 优惠金额 | `usageNo`；只对已核销返回首次金额；带 ID 时读冻结快照 | ✅ 快照核销已实施 |
| 6 | 释放（release） | 取消/超时释放 | `usageNo` → 券状态 | `usageNo`；只对已释放/过期/超时返回幂等 | ✅ |
| 7 | 退款（refund） | 已核销后按行/整单冲回 | `usageNo`、`refundNo`、行+数量 → 冲回金额 | `refundNo` 同号同参重放；同号异参 1000；同号跨单拒绝 | ✅ |
| 8 | 查询 | 查券包、退款明细、账单 | 用户/订单/退款单/日期/主体 → 列表/详情 | 只读（内部面 POST+管理令牌） | ✅ 券包；✅ 退款/主体账单/模板账单查询（V24）；○ 开放面租户自助查询 |
| 9 | 事件 / Webhook | 通知产品“发生了什么” | 发放/锁定/核销/退款/过期 → 事件 | 事件 ID 幂等（目标） | ◐ 内部事件；○ 对外 Webhook |
| 10 | 报表 / 结算数据 | 按租户/结算主体/模板汇总 | 日期范围 → 日汇总/明细 | 重跑幂等 | ✅ 模板日账单 + 主体日账单（V24，仅行级链路）；○ 导出/结算单/结算时点 |

### 2.1 调用前提

- **开放面**：每个请求必须带 `appId`、HMAC 签名、时间戳、nonce；缺签名/签名错/时间窗超出/nonce 重放一律拒绝（6xxx），不执行业务；
- **内部面写接口**：必须带 `X-Admin-Token`（或显式登记的业务写白名单），否则默认拒绝；`/api` 不做 appId 隔离，只用于平台运营；
- **归属**：开放面调用方的 `appId` 必须与模板/券/占用单的归属一致；越权拒绝，不返回资源内容；
- **写接口幂等键**：开放面写接口带 `X-Client-Token`；退款另带 `refundNo`；
- **参数校验**：非空、正数、长度、数组上限在入口校验；校验失败返回 `1000`（HTTP 200 的业务错误，不是 400）；超大请求由入口/网关限制（目标）。

### 2.2 退款契约（专项）

- **退款单号**：新接入方必须传 `refundNo`；不传时服务端生成 `AUTO:<usageNo>`，只适合“整单退一次”；`refundNo` 全局唯一，不按租户隔离；
- **请求粒度**：`items` 为空 = 退剩余全部（整单退语义）；非空 = 按行 + 数量部分退；
- **幂等**：同号同参重放返回首次结果；同号异参返回 1000；同号跨占用单返回 1000；
- **金额来源**：读核销时的行级分摊快照，不按当前模板/活动重算；
- **累计限制**：每行累计退款数量 ≤ 原数量；每行累计冲回 ≤ 原分账；同一占用单最多 50 次；
- **券处置**：部分退款券保持 `USED`；整单退完且券在有效期内回 `USABLE`，已过期转 `EXPIRED`；一券限退 3 次（当前全局）；
- **归属**：退款明细的 `settle_party_id` 从原分账行复制，不接收退款请求里的主体；
- **老式订单**：不带 `items` 的核销只能整单退，只写退款单、不写退款明细，不能进入按行/按主体结算。

### 2.3 每个原语的边界

- **建模板**：只定义规则，不发券；发布后核心规则不可变或必须版本化；
- **发券**：只负责“发出”，不负责“用户是否该得”；人群/资格由产品决定或走扩展点；
- **试算**：只算钱、不花钱、不占券；试算结果不锁定库存/券；带 `orderNo` 且开关开启时会写/复用快照并返回 `pricingId`，但不占券、不改券状态；
- **锁券**：占用券但不核销；锁窗口默认 30 分钟，与订单取消契约对齐；
- **核销**：支付成功后的记账；核销后券进入已核销，退款是唯一冲回路径；
- **释放**：取消/超时的回退；已核销/已退款不可释放；
- **退款**：只冲回优惠金额与出资归属，不负责用户实际收款；退款金额由订单按行实付计算；
- **查询**：只读，不产生资金/状态动作；
- **事件**：目标至少一次投递 + 消费方幂等；当前没有对外 Webhook，顺序/恰好一次不保证；
- **报表**：给财务/运营看数和结算，不执行打款。

## 3. 内核承诺

> 每条承诺都写：承诺什么、例子、怎么验证、当前状态。接入方只依赖 ✅ 的承诺；标 ◐/○ 的部分按 §1.4 的适用面理解。

### G1 金额守恒 ◐（仅行级链路）

**承诺（仅对带 `items` 的行级核销/退款）**：

- 同一占用单：`Σ 行分摊 = 券实际优惠`；
- 同一行：`平台承担 + 非平台承担 = 行优惠`；
- 同一占用单：`Σ 平台承担 = 总平台出资`，`Σ 非平台承担 = 总非平台出资`；
- 退款累计：`累计退款数量 ≤ 原数量`，`累计冲回金额 ≤ 原行优惠`，`累计冲回平台/非平台 ≤ 原分账`；
- **结算应付**（默认“商家自己收款、平台补差额”模式）：某结算主体的平台应付 ≈ 该主体行上的平台承担净额；非平台承担是商家/租户自己少收的钱，不是平台现金支出；
- 任何一条不成立，核销/退款事务回滚，不落半截账。

**不适用**：不带 `items` 的老式核销（只传 `discountAmt`）不写行级分账；老式退款只写退款单、不写退款明细；这两条链路不能套用 G1，也不能进入按主体的结算数据。

**例子**：订单 200 元，券 20 元（平台出资），分账 L1 12、L2 8；平台承担 20、非平台承担 0；平台应付 L1 所属主体 12、L2 所属主体 8。退 L1 一件（原 2 件）冲回 6，累计 6 ≤ 12。

**验证**：行级核销/退款守恒用例；封顶/单行上限/数量尾差；并发用例；老式链路另测“不写分账/不进账单”。

### G2 状态正确 ✅

**承诺**：

- 券、占用单只能走合法状态迁移；非法迁移返回明确错误码（如 4004/4006/3004），不做“看起来成功”的修改；
- 终态不会被普通业务动作改回；整单退款退券是显式政策例外（`USED → USABLE/EXPIRED`），一券限退 N 次；
- 重复请求按 §G3 的幂等表处理，不重复改状态。

**例子**：已核销的占用单再释放 → 4004；已退款的占用单再核销 → 4004；超时关闭后迟到的核销 → 4006（订单按无券价处理）。

**验证**：状态机单测；重复核销/释放/退款用例；并发状态竞争用例。

### G3 幂等与重试 ✅/◐

**逐原语幂等表**：

| 原语 | 幂等键 | 可重放的前置状态 | 重放返回 | 终态/异参 |
|---|---|---|---|---|
| 锁券 | `(orderNo, couponId)`（`usageNo` 由服务端生成） | 占用单仍 `OCCUPYING` | `duplicated=true`，券已锁定 | 已终结 → 4002；不比较额外参数 |
| 核销 | `usageNo` | 占用单 `CONFIRMED` | `duplicated=true` + 首次金额 | 其他终态 → 4004/4006；不比较新的 items/discountAmt |
| 释放 | `usageNo` | `RELEASED`/`EXPIRED`/`TIMEOUT_CLOSED` | 幂等成功 + 真实券状态 | `CONFIRMED`/退款态 → 4004；不比较 reason |
| 退款 | `refundNo` | 同号同参已成功 | 首次结果 | 同号异参 → 1000；同号跨占用单 → 1000 |
| 开放面写接口 | `X-Client-Token` | 同 token 同参已成功 | 首次响应（缓存） | 同 token 异参 → 6008；处理中 → 6009 |

**前提与限制**：

- `X-Client-Token` 幂等只对 `/open/v1` 的 POST 生效；`/api` 写接口不校验 token；
- 开放面在 Redis 不可用时按设计 **fail-open**（幂等缓存不可用，请求会再次执行）；业务层仍有的幂等键（`usageNo`/`refundNo`/领取 requestId）继续生效，但模板创建没有业务幂等键，Redis 故障窗口内重试可能创建两张模板；
- 锁券重试必须带同一 `(orderNo, couponId)`；首次响应丢失时调用方没有 `usageNo`，不能拿 `usageNo` 作为锁券重试键；服务端按 `BoundedKey` 折叠长订单号，快查与事务层必须用同一折叠规则（2026-10-18 已修残留快查键）；
- 退款同号异参返回 1000；`refundNo` 全局唯一，不按租户隔离；不传时生成 `AUTO:<usageNo>`，只适合整单退一次。

**例子**：支付回调重复推送 3 次核销，只有第一次改状态，后两次返回 `duplicated=true` 和首次金额；第 4 次在退款后到达 → 4004。

**验证**：幂等集成用例；重复消息用例；同号异参/跨单用例；Redis 故障 fail-open 用例。

### G4 价格一致（`pricingId`） ✅

**承诺（已实施，V23，灰度 `trade.pricing.enabled` 默认关）**：

- 试算返回 `pricingId`；**一次试算 = 一个快照**，覆盖商品行、券集合、每张券每行分摊、结算主体、模板规则摘要、`engineVersion`、`settlePartyEnabled`、`maxDiscountRatio`、归属（appId/userId/orderNo）、过期时间；
- 绑定：`pricingId` 必须匹配 `appId + userId + orderNo + 券集合`；不能跨订单/跨租户复用；锁券带 ID 时同事务写 `coupon_pricing_usage` 绑定并续期；
- 同摘要复用：`(appId,userId,orderNo,主体开关,标准化行,排序券集合)` 在 TTL 内复用；命中直接返回快照里冻结的响应，不重算；
- TTL：默认 120 分钟；锁券时续期到“锁窗 + 10 分钟宽限”；过期后带 ID 一律拒绝；
- 消费：锁券校验快照归属与券在快照的可用集合；核销使用快照金额/分摊/出资，**完全不读当前模板**；同一订单多张券可共用一个快照；
- 核销漏传 `pricingId` 时按锁券绑定自动解析；传了与绑定不同的 ID → 4007；
- **fail-closed**：带 `pricingId` 但过期/归属不符/券集合不一致/行不一致 → `4007 PRICING_SNAPSHOT_INVALID`，并进入 `CONFIRM_EXCEPTION`（券不回 `USABLE`）；
- 不带 `pricingId` 且无绑定的旧调用方：
  - 带 `items` 的核销 → 回退到现有整栈复算；
  - 不带 `items` 的老式核销 → 按调用方金额记账，不做门槛/范围/占比复算（见 G1 的“不适用”）；
- 已知边界：核销校验与事务之间有极小 TOCTOU 窗口；扩展结果结构已冻结但扩展框架未接线。

**验证**：`PricingSnapshotIntegrationTest` 14/14、`PricingSnapshotOpenApiIntegrationTest` 2/2、`PricingSnapshotPolicyTest` 3/3；回归 74 + 相邻 39 例全绿。

### G5 归属正确 ◐

**承诺**：

- **成本承担**：分账/退款明细记录平台/非平台承担；退款从原分账快照复制，不重算；
- **结算主体**：
  - 分账/退款明细记录每一行的结算主体（V22 已加 `app_id + settle_party_id`）；
  - 退款从原分账行复制结算主体，不从退款请求读取；
  - 平台券可以租户级（跨主体），也可以指定主体；**商家出资/共担券必须绑定一个主体**，只作用于该主体的行；
  - 模板上的“绑定主体”只对商家出资/共担券必填、发布后不可变；平台券的行主体按行解析，不能只靠模板字段；
- 没有结算主体的产品落 `__default__` 桶，不冒充真实主体。

**当前状态**：◐ V22 已落 `coupon_template.settle_party_id` + 分账/退款明细 `app_id/settle_party_id`；退款从原分账行复制主体；灰度开关 `trade.settle_party.enabled` 默认关（关闭时行为与旧版一致，所有行 `__default__`）；按主体日汇总已在 V24 补齐（历史 `__default__` 不可用于真实结算）；老式无 `items` 不写行级主体；灰度开启时商家/共担券缺主体/旧模板 `__default__` 不可用。

**验证**：A 券只命中 A 的行；A 只有 60 元、门槛 100 元时不可用（B 不能帮凑）；退 A 只冲 A；平台券跨 A/B 时按行拆分应付；旧调用方落 `__default__`。

### G6 租户隔离 ✅/◐（仅开放面）

**承诺（仅 `/open/v1`）**：

- 一个 `appId` 不能读写另一个 `appId` 的模板、券、占用单；越权返回 403/6011（或按存在性隐藏策略）；**存在性语义尚未统一（L63），在拍板前不承诺所有路径的 HTTP 映射完全稳定，见 ADR-0016 已知例外**；
- 配额、限流、配置、审计按 `appId` 隔离；
- `/api` 是平台运营面，不承诺多租户隔离；需要隔离的内部产品走 `/open/v1`；
- 管理面操作受令牌保护；用户级 RBAC 是目标态。

**当前状态**：✅ 开放面 appId 归属校验、分片、租户配置/配额；◐ `/api` 无 appId 隔离；◐ 管理面只有单一令牌，缺 RBAC 与租户生命周期。

**验证**：跨租户开放面读写/核销/退款全部拒绝；`/api` 隔离测试明确标“不适用”；角色矩阵用例（目标）。

### G7 审计 ◐

**承诺（当前）**：

- 核销/退款两个动钱动作已写审计：who/what/when/before-after/result + 哈希链；
- 审计异步写入，失败不影响主业务；失败只记录 ERROR，**当前没有重试队列、没有告警规则、JVM 崩溃可能丢队列中的记录**；
- 审计记录当前没有幂等键，`/api` 重试或开放面 Redis fail-open 时可能产生重复审计；
- 审计切面对 record 入参取不到 userId（可能为空）；业务异常统一记 `resultCode=500`，不是业务码。

**目标态**：

- 覆盖所有动钱/状态/管理动作；
- 审计查询/导出、覆盖矩阵、保留策略、哈希链校验任务；
- 失败告警/补偿，不静默丢；
- 与业务重试幂等。

**验证（目标）**：动钱/状态动作全覆盖；篡改可发现；按订单/用户/时间可查；失败有告警。

### G8 韧性 ◐

**承诺**：

- 对 Redis/MySQL 等依赖设置超时、熔断、限流、降级；不把依赖故障放大成全站故障；
- 重试有上限/退避，不无限重试；幂等保证重试安全；
- 降级有明确语义：哪些功能可降、降级后返回什么错误、恢复后如何收敛。

**当前状态**：◐ 已有超时/时间预算/熔断（主要覆盖领取链路）/限流/开关预案/发件箱；MQ 没有熔断，发件箱默认只 `log` 兜底；缺 SLO、依赖故障演练、重试预算、舱壁、降级矩阵、Runbook。

**边界**：

- `5001 DEGRADED` 只表示临时降级，可重试；长期下线/接口退役用 `6002/6010`，不要用开关假装永久下线；
- 熔断/降级不保证“所有链路”都覆盖，按 07 的成熟度逐步补。

**验证**：Redis/MySQL/MQ 故障注入；核心链路不雪崩；恢复后自动收敛；告警/手册可执行（目标）。

### G9 API 兼容 ◐

**承诺**：

- 字段只增不改；不删除已有字段、不改变已有字段语义；
- 破坏性变更出新版本（如 `/open/v2`），旧版本保留废弃期；
- 错误码稳定；新增错误码只增不改；
- 客户端应忽略未知字段（向前兼容）；
- 提供契约测试、变更日志、沙箱（目标态）。

**当前状态**：◐ 已有 `/open/v1`、稳定错误码；缺正式废弃策略、契约测试、SDK、沙箱、变更日志。

**验证**：契约测试；旧版本兼容用例；废弃公告与迁移演练。

### G10 结算数据 ✅/◐

**承诺**：

 - 模板日账单（✅，**只覆盖带 items 的行级链路**）；
- 按租户/结算主体/模板的日汇总（V24 ✅）；
- 正分账 − 退款明细 − 旧负行 = 净额；跨日退款记在退款日，允许负数；
- 重跑幂等；生成后自动 `reconcile`（主体合计 vs 模板账单）；
- 数据可导出/结算单/结算时点（目标态）；
- 只提供结算数据，不执行打款/开票。

**当前状态**：✅ 模板日账单 + 主体日账单（V24，仅行级链路；主体账单可用 `coupon.billing.settle-party.enabled=false` 回滚）；老式核销/退款不进账单；○ 导出/结算单/结算时点。

**验证**：同一模板多主体金额相加 = 模板账单；跨日退款负数；重跑结果不变；老式链路明确标“不可见”。

## 5. 扩展面

> 标准原语覆盖不了的产品特殊逻辑，通过受控扩展点接入；扩展不能破坏内核的状态机、金额守恒、幂等、隔离。

| 扩展点 | 用来做什么 | 机制 | 失败语义 | 状态 |
|---|---|---|---|---|
| 资格校验（Eligibility） | 判断用户/订单是否有资格用券 | 内部 SPI 或外部 Webhook | 失败默认拒绝（fail-closed） | ○ |
| 范围解析（Scope Resolver） | 把产品的品类/门店/会员等级映射成内核范围 | SPI/配置 | 失败默认拒绝 | ○ |
| 特殊定价（Pricing Policy） | 标准满减/满折表达不了的价格逻辑 | 第一版不做；优先标准策略组合。确需时只允许白名单 SPI，内核复核守恒 | 失败拒绝，不静默回退 | ○ |
| 出资解析（Funding Resolver） | 多预算账户/多主体出资 | SPI/配置 | 失败拒绝，不默认平台承担 | ○ |
| 结算适配（Settlement Adapter） | 把结算数据推给产品/财务系统 | 文件/API/Webhook | 失败重试/对账 | ○ |
| 通知（Notification） | 发券/核销/退款事件通知 | Webhook/MQ | 异步重试，不阻塞主链路；顺序/恰好一次不保证 | ◐ 内部事件；○ 对外 Webhook |

**扩展规则**：

- 扩展点有版本、超时、重试、降级、审计；不能无限等待；
- 扩展不能修改内核的金额/状态结果，只能提供输入或附加动作；
- 金额计算是内核职责：特殊定价扩展不能直接返回“最终优惠金额”，只能提供参数或候选方案，由内核复核守恒后落账；
- **默认 fail-closed**：资格/范围/定价/出资扩展失败时拒绝业务，不静默改价或转嫁资损；任何 fallback 必须由产品显式配置并审计/告警；
- 外部产品的扩展走 Webhook/API，不把外部代码装进内核；
- 不在扩展点里做营销、页面、投放；
- 事件当前只保证“内部事件写入”；对外 Webhook 的至少一次、去重窗口、Schema 版本、死信/重试是目标态。

## 6. 错误与重试契约

### 6.1 逐码表

### 6.2 重试规则

1. **先查后重试**：超时/未知结果时，用幂等键查询首次结果，再决定是否重试；
2. **同键重试**：锁券用同一 `(orderNo, couponId)`；核销/释放用同一 `usageNo`；退款用同一 `refundNo`；开放面 HTTP 写接口用同一 `X-Client-Token`；
3. **不换键**：换新键重试可能产生第二次业务动作；
4. **退避**：5xx/限流按指数退避 + 抖动；不要固定高频重试；
5. **不可重试**：参数错误、越权、状态死局、签名错误、重放——重试不会变好；
6. **同键异参**：只有退款（`requestDigest`）和开放面 token 层会校验；锁/核销/释放以首次结果为准，不比较参数差异。

### 6.3 冲突语义

- `4002`：状态被并发变更；刷新后若目标动作仍可能成功则重试，已进入终态则不重试；
- `4004`：占用单状态冲突，通常是重复/迟到动作，按终态处理；
- `4006`：超时关闭，订单按无券价处理，不要重试核销；
- `6008`：同一 token 不同参数，说明调用方复用错了 token，不要重试。

## 7. 版本与兼容

1. **版本路径**：开放面 `/open/v1`；破坏性变更出 `/open/v2`；

7. **沙箱**：外部产品先在沙箱跑通试算/锁/核销/退款，再上生产（目标态）。

## 9. 内核不保证什么

- 不保证产品政策正确（门槛/力度/范围配错，内核按配置执行）；
- **不认证终端用户身份**：内核只认证应用（appId）；`userId` 由调用方提供并信任，调用方必须保证其真实性和归属；
- 不保证订单真实性（假单、刷单、自产自销需要订单/支付/物流证据）；
- 不保证营销效果（发多少、转化多少、ROI）；
- 不执行支付/打款/开票/税务；
- 不替外部系统修数据（订单传错金额/主体，内核只能在契约内拒绝）；
- 不替代完整合规认证（提供审计/权限/保留基础能力，不替代法律审查）；
- 不保证扩展点内部逻辑正确（扩展由产品/扩展提供方负责，内核保证调用边界与失败语义）；
- 不保证事件顺序与恰好一次（目标至少一次 + 消费方幂等；当前对外 Webhook 未实现）；
- 不保证老式核销/退款（不带 items）的行级分账、出资明细、日账单可见性；
- 不保证 `/api` 的多租户隔离与 token 幂等（它只用于平台运营）。

## 10. 接入验收清单

### 10.1 当前可验收（✅）

| 项 | 通过标准 |
|---|---|
| 认证（开放面） | 签名/时间窗/nonce 正确；错误密钥/重放/过期全部拒绝 |
| 锁券幂等 | 同一 `(orderNo, couponId)` 重放返回 `duplicated=true`；终态返回 4002 |
| 核销/释放幂等 | 已核销/已释放/过期/超时按 §G3 表返回；其他终态返回 4004/4006 |
| 退款幂等 | 同 `refundNo` 同参返回首次结果；同号异参 1000；同号跨单拒绝 |
| 金额（行级） | 行级核销/退款金额与手工核算一致；守恒断言通过 |
| 状态 | 非法状态迁移返回明确错误；终态不被普通动作改回 |
| 隔离（开放面） | 跨租户读写全部拒绝；`/api` 不在本项范围 |
| 错误处理 | 按 §6 表区分可重试/不可重试；不无限重试 |
| 审计（当前） | 核销/退款有审计记录，含前后快照和哈希链 |
| 券包查询 | `GET /open/v1/coupons` 返回本应用本用户的券 |

### 10.2 目标态验收（◐/○）

| 项 | 目标 |
|---|---|
| 价格快照 ✅ | 试算后改模板，带 `pricingId` 核销金额不变；过期/跨租户/券集合不一致拒绝（已由 14+2 用例覆盖） |
| 结算主体 | 一单多主体归属正确；平台券跨主体拆分应付；商家出资券只作用绑定主体 |
| 结算数据 | 按主体日汇总与模板账单对得上；跨日退款负数 |
| 审计查询 | 按订单/用户/时间查；篡改可校验；失败有告警 |
| 管理面 RBAC | 查看/操作/审批角色矩阵；跨租户/越权拒绝 |
| API 版本/契约 | 契约测试通过；旧版本兼容；废弃公告 |
| 事件/Webhook | 至少一次、消费方幂等、Schema 版本、重试/死信 |
