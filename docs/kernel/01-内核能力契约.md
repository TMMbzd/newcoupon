## 0. 这份契约怎么用

1. 产品接入前先读 00 和本文，确认“内核做什么、产品做什么”；
2. 只依赖标为 ✅ 的能力；标为 ◐/○ 的能力，接入前先与内核团队确认；
3. 如果代码行为与本文不一致，以本文为**目标态**、以 `docs/STATUS.md` 与测试为**真实态**，把差距登记下来，不默认“文档写的就是现在能用的”；
4. 本文只写**能力契约**，不写具体字段；字段见 03，表结构见 02；
5. 契约变更走版本：字段只增不改，破坏性变更出新版本。

## 1. 总则

### 1.1 机制与政策分离

- **内核保证机制**：怎么算、怎么锁、怎么核、怎么退、怎么记账、怎么审计、怎么隔离；
- **产品决定政策**：发什么券、门槛多少、发给谁、什么时候发、怎么营销、怎么结算；
- **产品配错政策，内核按配置执行**：例如产品把“满 0 减 100”配上，内核会按这个规则算；政策合理性由产品和运营负责。

### 1.2 租户与结算主体

- 租户 = `appId`，是数据隔离、配额、配置、审计的边界；
- 结算主体 = 优惠最终算到谁头上、平台和谁结算；可以是商家、门店、经销商、业务单元，也可以就是租户自己；
- 结算主体是**可选维度**；没有细分主体的产品落 `__default__` 桶，不被强迫引入“商家”概念；
- 商家出资/共担券在“有结算主体”的租户里必须绑定主体，避免 A 的券扣 B 的钱。

### 1.3 契约面

本契约覆盖四个面：

| 面 | 内容 | 详见 |
|---|---|---|
| API 面 | 建模板、发券、试算、锁/核销/释放/退款、查询 | 03 |
| 事件面 | 券发放/锁定/核销/退款/过期等事件与 Webhook | 03 |
| 配置面 | 券类型、范围、叠加、出资、限领、退款政策 | 本文 §4 + 03 |
| 扩展面 | 资格、范围、定价、出资、结算、通知 | 本文 §5 + 04 |

## 2. 能力原语

> 原语 = 内核提供的最小能力单元；产品用这些原语组合自己的业务流程。

| # | 原语 | 做什么 | 关键输入/输出 | 幂等 | 状态 |
|---|---|---|---|---|---|
| 1 | 建模板 / 发布 / 查询 | 定义一类券的规则并发布 | 模板配置 → 模板 ID/状态 | 建模板可用 `X-Client-Token`；发布/查询幂等 | ✅ |
| 2 | 发券（领取/批量/定向） | 把券发给用户 | 模板、用户、数量 → 用户券 ID/结果 | 领取用 `X-Client-Token`；批量按批次号 | ✅ 领取；◐ 批量/定向 |
| 3 | 试算（calculate） | 下单前算可用券、优惠、分摊 | 用户、商品行、券列表 → 优惠/分摊/不可用原因 | 只读，天然幂等 | ✅；○ `pricingId` |
| 4 | 锁券（lock） | 下单时占用券 | 订单号、用户、券 → `usageNo` | `usageNo`/`X-Client-Token` | ✅ |
| 5 | 核销（confirm） | 支付成功后记账 | `usageNo`、商品行/金额 → 优惠金额 | `usageNo` 重放 | ✅；○ 价格快照核销 |
| 6 | 释放（release） | 取消/超时释放 | `usageNo` → 券状态 | `usageNo` 重放 | ✅ |
| 7 | 退款（refund） | 已核销后按行/整单冲回 | `usageNo`、`refundNo`、行+数量 → 冲回金额 | `refundNo` 重放 | ✅ |
| 8 | 查询 | 查券包、占用单、退款明细 | 用户/订单/退款单 → 列表/详情 | 只读 | ✅ 券包/退款明细；◐ 管理查询 |
| 9 | 事件 / Webhook | 通知产品“发生了什么” | 发放/锁定/核销/退款/过期 → 事件 | 事件 ID 幂等 | ◐ 内部事件；○ 对外 Webhook |
| 10 | 报表 / 结算数据 | 按租户/结算主体/模板汇总 | 日期范围 → 日汇总/明细 | 重跑幂等 | ✅ 模板日账单；○ 结算主体日汇总 |

### 2.1 调用前提

- **开放面**：每个请求必须带 `appId`、HMAC 签名、时间戳、nonce；缺签名/签名错/时间窗超出/nonce 重放一律拒绝（6xxx），不执行业务；
- **内部面写接口**：必须带 `X-Admin-Token`（或显式登记的业务写白名单），否则默认拒绝；
- **归属**：调用方的 `appId` 必须与模板/券/占用单的归属一致；越权请求拒绝，不返回资源内容；
- **写接口幂等键**：开放面写接口带 `X-Client-Token`；退款另带 `refundNo`；
- **参数校验**：非空、正数、长度、数组上限在入口校验；校验失败返回 1000，不进入业务。

### 2.2 每个原语的边界

- **建模板**：只定义规则，不发券；发布后核心规则不可变或必须版本化；
- **发券**：只负责“发出”，不负责“用户是否该得”；人群/资格由产品决定或走扩展点；
- **试算**：只算钱、不花钱、不占券；试算结果不锁定库存/券；
- **锁券**：占用券但不核销；锁窗口默认 30 分钟，与订单取消契约对齐；
- **核销**：支付成功后的记账；核销后券进入已核销，退款是唯一冲回路径；
- **释放**：取消/超时的回退；已核销/已退款不可释放；
- **退款**：只冲回优惠金额与出资归属，不负责用户实际收款；退款金额由订单按行实付计算；
- **查询**：只读，不产生资金/状态动作；
- **事件**：至少一次投递 + 消费方幂等；不保证严格一次；
- **报表**：给财务/运营看数和结算，不执行打款。

## 3. 内核承诺

> 每条承诺都写：承诺什么、例子、怎么验证、当前状态。接入方只依赖 ✅ 的承诺。

### G1 金额守恒 ✅

**承诺**：

- 同一占用单：`Σ 行分摊 = 券实际优惠`；
- 同一行：`平台承担 + 商家承担 = 行优惠`；
- 同一占用单：`Σ 平台承担 = 总平台出资`，`Σ 商家承担 = 总商家出资`；
- 退款累计：`累计退款数量 ≤ 原数量`，`累计冲回金额 ≤ 原行优惠`，`累计冲回平台/商家 ≤ 原分账`；
- 任何一条不成立，核销/退款事务回滚，不落半截账。

**例子**：订单 200 元，券 20 元，分账 L1 12、L2 8；平台承担 20、商家 0；则 `12+8=20`、`12+0=12`、`8+0=8`、`20+0=20`。退 L1 一件（原 2 件）冲回 6，累计退款 6 ≤ 12。

**验证**：核销/退款守恒用例；边界（封顶、单行上限、数量尾差）用例；并发用例。

### G2 状态正确 ✅

**承诺**：

- 券、占用单只能走合法状态迁移；非法迁移返回明确错误码（如 4004/4006/3004），不做“看起来成功”的修改；
- 终态不会被普通业务动作改回；整单退款退券是显式政策例外（`USED → USABLE/EXPIRED`），一券限退 N 次；
- 重复请求返回幂等结果，不重复改状态。

**例子**：已核销的占用单再释放 → 4004；已退款的占用单再核销 → 4004；超时关闭后迟到的核销 → 4006（订单按无券价处理）。

**验证**：状态机单测；重复核销/释放/退款用例；并发状态竞争用例。

### G3 幂等与重试 ✅

**承诺**：

- 锁券：同一 `usageNo` 且占用单仍“占用中” → 幂等成功；已终结 → 状态冲突（不能谎报“已锁定”）；
- 核销/释放：已处于目标终态 → 幂等成功；其他终态 → 明确拒绝（如 4004/4006）；
- 退款：同一 `refundNo` 同参重放返回首次结果；同号异参返回冲突；同号跨占用单拒绝；
- 开放面写接口：同一 `X-Client-Token` 同参重放返回首次响应；同 token 异参返回 6008；处理中返回 6009；
- 超时未知结果：先按幂等键查询，再决定是否重试；不要换新键重试。

**例子**：支付回调重复推送 3 次核销，只有第一次改状态，后两次返回 `duplicated=true` 和首次金额。

**验证**：幂等集成用例；重复消息用例；同号异参/跨单用例。

### G4 价格一致（`pricingId`） ○

**承诺（目标态）**：

- 试算返回 `pricingId`，快照包含商品行、券规则、每张券每行分摊、结算主体、归属（appId/userId/orderNo）、过期时间；
- 锁券/核销带 `pricingId` 时，按快照价格和分摊执行，不按模板当前值重算；
- 带 `pricingId` 但快照过期、归属不符、券集合不一致 → **拒绝**（不能静默改价），并记录降级计数；
- 不带 `pricingId` 的旧调用方 → 回退到现有整栈复算，行为不变（这是兼容路径，不是新接入方的默认路径）。

**当前状态**：○ 未实现。当前核销会按订单级整栈复算，若试算后模板被改，价格可能变化。

**验证**：试算后改模板、带快照核销金额不变；过期/跨租户/券集合不一致拒绝；旧调用方兼容。

### G5 归属正确 ◐

**承诺**：

- 分账/退款明细记录 `appId` + 结算主体；退款从原分账快照复制归属，不从退款请求读取；
- 平台券可跨结算主体，平台承担按行拆到各主体；商家出资/共担券必须绑定主体，只作用于该主体的行；
- 没有结算主体的产品落 `__default__` 桶，不冒充真实主体。

**当前状态**：◐ 行级分账/退款已有，但还没有结算主体字段与过滤；“结算主体可选”是内核 v1 第 1 环目标。

**验证**：A 券只命中 A 的行；A 只有 60 元、门槛 100 元时不可用（B 不能帮凑）；退 A 只冲 A；旧调用方落 `__default__`。

### G6 租户隔离 ✅/◐

**承诺**：

- 一个 `appId` 不能读写另一个 `appId` 的模板、券、占用单；越权返回 403/6011（或按存在性隐藏策略）；
- 配额、限流、配置、审计按 `appId` 隔离；
- 管理面操作受令牌/角色保护。

**当前状态**：✅ appId 归属校验、分片、租户配置/配额；◐ 管理面只有单一令牌，缺 RBAC 与租户生命周期。

**验证**：跨租户读/写/核销/退款全部拒绝；角色矩阵用例；隔离集成测试。

### G7 审计 ✅/◐

**承诺**：

- 动钱、改状态、管理配置的动作记录 who/what/when/before/after/result；
- 审计日志防篡改（哈希链）；可按订单/用户/时间查询（目标态）；
- 审计失败不影响主业务，但必须记录/告警，不静默丢（当前为部分具备）；审计记录不因业务重试而重复污染。

**当前状态**：✅ @AuditLog、哈希链、异步写入、核销/退款已挂审计；◐ 查询/导出、覆盖矩阵、保留策略、校验任务待补。

**验证**：动钱路径全覆盖；篡改可发现；按订单可查；异步失败有告警。

### G8 韧性 ◐

**承诺**：

- 对 Redis/MySQL/MQ 等依赖设置超时、熔断、限流、降级；不把依赖故障放大成全站故障；
- 重试有上限/退避/预算，不无限重试；幂等保证重试安全；
- 降级有明确语义：哪些功能可降、降级后返回什么错误、恢复后如何收敛。

**当前状态**：◐ 已有超时/时间预算/熔断/限流/开关预案/发件箱；缺 SLO、依赖故障演练、重试预算、舱壁、降级矩阵、Runbook。

**验证**：Redis/MySQL/MQ 故障注入；核心链路不雪崩；恢复后自动收敛；告警/手册可执行。

### G9 API 兼容 ◐

**承诺**：

- 字段只增不改；不删除已有字段、不改变已有字段语义；
- 破坏性变更出新版本（如 `/open/v2`），旧版本保留废弃期；
- 错误码稳定；新增错误码只增不改；
- 提供契约测试、变更日志、沙箱（目标态）。

**当前状态**：◐ 已有 `/open/v1`、稳定错误码；缺正式废弃策略、契约测试、SDK、沙箱、变更日志。

**验证**：契约测试；旧版本兼容用例；废弃公告与迁移演练。

### G10 结算数据 ✅/○

**承诺**：

- 提供按模板的日账单（已有），目标是按租户/结算主体/模板的日汇总与明细；
- 正分账 − 退款明细 = 净额；跨日退款记在退款日，允许负数；
- 重跑幂等；数据可导出（目标态）；
- 只提供结算数据，不执行打款/开票。

**当前状态**：✅ 模板日账单；○ 结算主体日汇总、导出、结算单。

**验证**：同一模板多主体金额相加 = 模板账单；跨日退款负数；重跑结果不变。

## 4. 配置面

> 产品通过配置表达规则，不改内核代码。配置项的具体字段/接口见 03；这里定义“有哪些、谁负责、能不能改”。

| 配置项 | 含义 | 默认/约束 | 谁设置 | 发布后可变性 |
|---|---|---|---|---|
| 券类型 | 满减/满折/无门槛 | 必填 | 产品 | 发布后不可变 |
| 面额/折扣/上限 | 优惠力度 | 满减面额 ≤ 门槛；满折有上限 | 产品 | 发布后不可变 |
| 门槛 | 最低可用金额 | 满减 >0；无门槛=0 | 产品 | 发布后不可变 |
| 适用范围 | 全场/品类/SKU/结算主体 | 非全场必须有范围值 | 产品 | 发布后不可变或版本化 |
| 叠加层级 | 店铺级/平台级 | 默认店铺级 | 产品 | 发布后不可变 |
| 互斥组 | 同层同组互斥 | 空=默认互斥 | 产品 | 发布后不可变或版本化（影响叠加结果） |
| 出资方 | 平台/商家/共担 | 共担必须有比例 | 产品 | 发布后不可变 |
| 有效期 | 固定区间/领取后 N 天 | 必填 | 产品 | 发布后不可变（实例快照） |
| 限领 | 每人/每天/总量 | 必填 | 产品 | 可调整，需审计 |
| 退款政策 | 最多退款次数、退券次数、整单退是否退券 | 默认 50/3/是 | 当前全局；租户级为目标（○） | 可配置，需审计 |
| 价格快照开关 | 是否启用 `pricingId` | 默认关（灰度，○） | 内核/产品 | 可切换，需审计 |
| 结算主体 | 商家/门店/业务单元 | 可空，空=租户级 | 产品 | 发布后不可变 |

**不可变原则**：面额、门槛、范围、出资、结算主体、有效期等核心规则，发布后不可直接改；要改就新建模板/新版本。模板变更影响历史券的边界，见 02。

## 5. 扩展面

> 标准原语覆盖不了的产品特殊逻辑，通过受控扩展点接入；扩展不能破坏内核的状态机、金额守恒、幂等、隔离。

| 扩展点 | 用来做什么 | 机制 | 失败语义 | 状态 |
|---|---|---|---|---|
| 资格校验（Eligibility） | 判断用户/订单是否有资格用券 | 内部 SPI 或外部 Webhook | 失败默认拒绝（fail-closed） | ○ |
| 范围解析（Scope Resolver） | 把产品的品类/门店/会员等级映射成内核范围 | SPI/配置 | 失败默认拒绝 | ○ |
| 特殊定价（Pricing Policy） | 标准满减/满折表达不了的价格逻辑 | 第一版不做；优先用标准策略组合。确需时只允许白名单 SPI，且内核仍复核金额守恒 | 失败回退标准策略并告警 | ○ |
| 出资解析（Funding Resolver） | 多预算账户/多主体出资 | SPI/配置 | 失败默认平台/租户承担并告警 | ○ |
| 结算适配（Settlement Adapter） | 把结算数据推给产品/财务系统 | 文件/API/Webhook | 失败重试/对账 | ○ |
| 通知（Notification） | 发券/核销/退款事件通知 | Webhook/MQ | 异步重试，不阻塞主链路 | ◐ 内部事件 |

**扩展规则**：

- 扩展点有版本、超时、重试、降级、审计；不能无限等待；
- 扩展不能修改内核的金额/状态结果，只能提供输入或附加动作；
- 金额计算是内核职责：特殊定价扩展不能直接返回“最终优惠金额”，只能提供参数或候选方案，由内核复核守恒后落账；
- 外部产品的扩展走 Webhook/API，不把外部代码装进内核；
- 扩展失败的业务语义必须在接入时写清楚（fail-open 还是 fail-closed）；
- 不在扩展点里做营销、页面、投放。

## 6. 错误与重试契约

### 6.1 错误码家族

| 家族 | 含义 | 例子 | 可重试 |
|---|---|---|---|
| 0 | 成功 | 0 | — |
| 1xxx | 参数/重复请求 | 1000 参数错误、1001 幂等命中 | 1000 不重试；1001 按成功处理 |
| 2xxx | 模板 | 2001 模板不存在、2003 状态不允许 | 一般不重试 |
| 3xxx | 库存/限领/券不可用 | 3001 售罄、3002 限领、3004 券不可用 | 3001/3002 不重试；3004 看原因 |
| 4xxx | 用户券/占用单 | 4001 券不存在、4002 状态冲突、4004 占用单状态冲突、4006 超时关闭 | 4002 看新状态（可能可重试）；4004 不重试；4006 按无券价处理 |
| 5xxx | 系统/降级 | 5000 系统繁忙、5001 降级、5003 预算耗尽 | 可重试（带退避/幂等） |
| 6xxx | 开放平台 | 6001 签名缺失、6005 nonce 重放、6006 限流、6008 token 冲突、6012 缺 token | 6001/6003/6005/6012 不重试；6006/6009 可稍后重试 |

### 6.2 重试规则

1. **先查后重试**：超时/未知结果时，用幂等键查询首次结果，再决定是否重试；
2. **同键重试**：锁/核销/释放用同一 `usageNo`；退款用同一 `refundNo`；HTTP 写接口用同一 `X-Client-Token`；
3. **不换键**：换新键重试可能产生第二次业务动作；
4. **退避**：5xx/限流按指数退避 + 抖动；不要固定高频重试；
5. **不可重试**：参数错误、越权、状态死局、签名错误、重放——重试不会变好。

### 6.3 冲突语义

- `4002`：状态被并发变更；刷新后若目标动作仍可能成功则重试，已进入终态则不重试；
- `4004`：占用单状态冲突，通常是重复/迟到动作，按终态处理；
- `4006`：超时关闭，订单按无券价处理，不要重试核销；
- `6008`：同一 token 不同参数，说明调用方复用错了 token，不要重试。

## 7. 版本与兼容

1. **版本路径**：开放面 `/open/v1`；破坏性变更出 `/open/v2`；
2. **字段兼容**：只增不改；新增字段可选；不删除、不改语义、不改默认值；
3. **废弃流程**：公告 → 双版本并行 → 迁移期 → 下线；迁移期长度按接入方数量定；
4. **错误码**：只增不改；已有错误码语义不变；
5. **契约测试**：提供方维护契约用例；接入方接入前跑一遍；
6. **变更日志**：每次 API/事件变更记录版本、影响、迁移方式；
7. **沙箱**：外部产品先在沙箱跑通试算/锁/核销/退款，再上生产（目标态）。

## 8. 配额、限流与运行边界

| 项 | 当前/默认 | 说明 |
|---|---|---|
| 锁券窗口 | 30 分钟 | 与订单取消契约对齐；超时由系统收场 |
| 单次试算券数 | 最多 10 张 | 防止组合爆炸 |
| 单次商品行 | 试算最多 100 行；核销当前未单独限制（目标统一 100 行） | 防止超大订单 |
| 退款次数 | 每占用单最多 50 次 | 对齐微信支付单品退款 |
| 退券次数 | 每券最多 3 次 | 防“下单-退款-再用” |
| 单笔优惠占比 | 默认 80% | 超过拒绝核销；当前按整单金额，目标按“券适用范围内金额”（避免其他结算主体的金额帮本券过防线） |
| 核销速率告警 | 默认 600 次/分钟/appId（开放面） | 只告警不拦截；内部面无 appId 时不计 |
| 租户 QPS/日配额 | 按租户配置 | 超限返回 6006/6007 |
| 请求大小/字段长度 | 按 DTO 校验 | 超限返回 1000/400 |

> SLO（可用性、P95/P99、错误率）在容量压测与试点后填，见 07。

## 9. 内核不保证什么

- 不保证产品政策正确（门槛/力度/范围配错，内核按配置执行）；
- 不保证订单真实性（假单、刷单、自产自销需要订单/支付/物流证据）；
- 不保证营销效果（发多少、转化多少、ROI）；
- 不执行支付/打款/开票/税务；
- 不替外部系统修数据（订单传错金额/主体，内核只能在契约内拒绝）；
- 不替代完整合规认证（提供审计/权限/保留基础能力，不替代法律审查）；
- 不保证扩展点内部逻辑正确（扩展由产品/扩展提供方负责，内核保证调用边界与失败语义）。

## 10. 接入验收清单

| 项 | 通过标准 |
|---|---|
| 认证 | 签名/时间窗/nonce 正确；错误密钥/重放/过期全部拒绝 |
| 幂等 | 锁/核销/释放/退款同键重放返回首次结果；同键异参冲突 |
| 金额 | 试算/核销/退款金额与手工核算一致；守恒断言通过 |
| 状态 | 非法状态迁移返回明确错误；终态不被普通动作改回 |
| 隔离 | 跨租户读写全部拒绝 |
| 错误处理 | 按错误码家族区分可重试/不可重试；不无限重试 |
| 审计 | 动钱/状态动作可按订单查；审计失败有记录/告警，不静默丢（目标态） |
| 兼容 | 字段只增不改；旧版本调用不受影响 |
| 观测 | 接入方有请求量/错误/延迟指标；关键错误有告警 |
| 结算 | 日汇总/明细与核销/退款数据对得上 |
