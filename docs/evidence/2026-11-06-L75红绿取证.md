## 1. 红：修复前，窗口攻击用例失败

命令：

```bash
mvn -o test -Dtest=L75ConfirmToctouIntegrationTest -Dsurefire.failIfNoSpecifiedTests=false
```

输出（节选）：

```text
[ERROR] Tests run: 6, Failures: 4, Errors: 0, Skipped: 0
[ERROR]   L75ConfirmToctouIntegrationTest.siblingReleaseInWindowRejectsSnapshotConfirm:187
          Expecting code to raise a throwable.

          Expecting code to raise a throwable.

          Expecting code to raise a throwable.

```

EXIT=1。失败的四例正是：

| 用例 | 窗口注入点 | 修复前行为（错误） |
|---|---|---|
| T1 sibling 释放（快照路径） | `prepareConfirm` 返回后 | 按失效快照核销成功 |
| T2 sibling 退款（快照路径） | `prepareConfirm` 返回后 | 售后态下仍核销成功 |
| T5 旧式金额 + sibling 已退款 | 事务外无订单级校验 | 售后态下仍核销成功 |
| T6 L64 复算 + sibling 释放 | `calculateForOrderConfirm` 返回后 | 按失效券集合核销成功 |

T3（幂等重放）与 T4（正常顺序核销）在修复前就是绿的——它们是"不误伤"对照，
修复后必须仍然绿。
