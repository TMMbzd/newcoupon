## 4. 本轮新发现（未修，建议下个会话登记）

1. **JDBC URL 缺 `allowPublicKeyRetrieval=true`**（详情见 MySQL 报告 §5.1）：MySQL 容器重启后 `caching_sha2_password` 全量认证失败，Hikari 建不起新连接，应用**永远无法自愈**。当前 dev 的 `spring.datasource.url` 与 `coupon.sharding.url` 都没有该参数；演练脚本用启动参数覆盖。建议修 dev 配置（生产走 SSL 或显式参数），并补一个"重启 MySQL 后应用自愈"的集成验证。
2. **WorkerIdLease 关闭时不释放租约**（详情见双实例报告 §5）：SIGTERM 退出后 `c:id:worker:{id}` 仍保留到 60s TTL；固定 `WORKER_ID` 的滚动重启会在最长 60 秒内起不来（`WORKER_ID=101 已被其他实例占用`）。冒烟改用自动分配 workerId 绕开。建议修关闭释放并补"启动→关闭→同 ID 再启动"测试。
3. **dly 的 +52 大窗**（详情见压测报告 §4.2）：冷启动 1000 并发首次受理时，Redis dly 与 DB 目标的瞬态差可以远大于 1（实测 +52）。本轮 L78 修复只容 ±1；是否需要更大容差/拆族阈值需要再评估（放大容差可能放过真漂移）。
