## 2. 架构与测试环境策略（为什么这样驱动）

- **JUnit 集成测试起服务**：`ConsoleE2eIntegrationTest` 复用 `ShardedIntegrationTestSupport`
  共享基座（Testcontainers MySQL/Redis）+ `@SpringBootTest(RANDOM_PORT)`——服务端是**真实应用**，
  不是 mock；预置模板走真实 API 建（旧令牌），模板名经环境变量传给浏览器侧断言。
- **Playwright 独立进程**：`ProcessBuilder` 在 console/ 目录拉起 `npx playwright test`，
  地址/凭据/模板名经 `CONSOLE_BASE_URL` 等环境变量注入；断言**退出码 0 + 输出含 5 passed**。
  选独立进程而非 JVM 内嵌 Playwright-for-Java：浏览器栈（Node/chromium 版本矩阵）与 JVM
  构建解耦，Node 侧崩溃只是子进程退出码非 0，不拖垮测试 JVM 与 Testcontainers 生命周期。
- **五用例各拿独立浏览器上下文**（Cookie 隔离），需要登录态的用例自己从登录走起——
  单独 `-g` 跑任意一条都成立；`workers: 1` 串行（五步是一条业务流）。
