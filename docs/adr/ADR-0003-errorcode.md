# ADR-0003: 统一响应体 + 分段错误码 + 全局异常处理

- **状态**：已接受（2026-09-03）
- **背景**：接口的错误如何表达？裸抛异常 / 各接口自定义返回 / 统一规范。
- **决策**：所有 REST 接口返回 `Result<T>`（code/message/data）；错误码按域分段（0 成功 / 1xxx 参数 / 2xxx 模板 / 3xxx 领券 / 4xxx 用券 / 5xxx 系统）；异常由 `@RestControllerAdvice` 全局收敛。
- **理由**（对标 docs/01 第 4.8 节接口契约；分段规则的现行载体是 `ErrorCode` 枚举 javadoc 与根 README 工程规范表）：
  1. 上游要**程序化**区分"已售罄(3001，不可重试)"和"系统繁忙(5000，可重试)"——字符串只能给人看，错误码才能给程序做分支；
  2. 分段让错误码可预测、可检索：从码值就能定位到出事的域，日志告警按段聚合；
  3. 安全基线：堆栈只进日志不出响应（堆栈含类名/行号/SQL 片段，是攻击者的免费情报）；预期内失败(WARN)与预期外错误(ERROR)分开，告警只对 ERROR 响铃，防止业务失败刷屏淹没真事故。
- **后果**：新增接口必须用 Result 包裹、新错误码必须归段；错误码表成为对外契约的一部分，变更需评审。
