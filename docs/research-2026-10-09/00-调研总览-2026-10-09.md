## 三、核心发现摘要

### 3.1 当前项目状态评估

**✅ 保留价值**（已验证质量高）：
- S1 开放接入层：签名/幂等/配额/越权防护（442 测试零失败）
- S2 流量治理：租户配置中心/限流/熔断/三级预案
- S3 Sentinel 集群流控：Token Server + 跨进程验收
- 基础设施：Redis/MySQL/RocketMQ/Caffeine/XXL-JOB

**⚠️ 需重构**：
- P2 库存架构：过度复杂（16桶+世代隔离），改造成异步模式
- 术语对齐：世代→批次快照、巡检→轧账、deep→平账

**❌ 核心缺失**（最严重）：
- 优惠计算引擎：零实现（discountAmt 由调用方传入）
- 结算对账：coupon_share_detail 表已建但零写入
- 运营管理：无活动配置、无人群包、无触达通道
- 前端应用：零前端代码
- 风控增强：无设备指纹、无行为分析、无欺诈防控

## 八、关键决策记录

### 8.1 当前代码库处理方案

**决策**: 保留改造（推荐指数 8/10）

**理由**：
1. ✅ S1/S2/S3 基础设施质量高（442 测试零失败）
2. ✅ 技术栈选型合理（Spring Boot 3 + Redis + RocketMQ）
3. 🔄 P2 库存架构过度复杂，但可改造而非废弃
4. ➕ 核心业务缺失，但基础设施可复用

**替代方案对比**：
- 方案 B（推倒重来）：时间成本高（6-8 周），不推荐
- 方案 C（双轨并行）：维护成本翻倍，不推荐

### 8.2 异步扣减实施方案

**决策**: 同步+异步双模式并存

**架构**：
```
同步模式（当前）：
- 场景：QPS < 5000，常规领券
- 流程：Redis Lua 预扣 + DB 实时写入
- 状态：已完成 ✅

异步模式（新增）：
- 场景：QPS > 10000，秒杀场景
- 流程：Redis DECR → MQ → 消费端落库
- 状态：待实施 ➕
```

**业界对标**：
- 阿里：Tair(QPS 51万) + RocketMQ
- 京东：Redis Cluster + RabbitMQ
- 美团：Redis Cluster + Kafka

### 8.3 优惠计算引擎实施方案

**决策**: 分阶段实现

**Phase 1（最小可用版）**：
- 责任链 + 策略模式
- 满减/折扣两种券
- 单券试算接口
- 10 条黄金用例

**Phase 4（增强版）**：
- 动态规划最优组合
- 返回 Top3 方案
- 配置期校验（防过深）

## 九、风险与挑战

### 9.1 技术风险

1. **P2 库存架构改造**
   - 风险：16桶+世代隔离复杂度高，改动可能引入 Bug
   - 缓解：保留现有同步模式，异步模式独立实现

2. **前端开发能力**
   - 风险：用户无前端经验
   - 缓解：使用 Ant Design Pro 脚手架，降低门槛

3. **WSL2 资源限制**
   - 风险：~6.6G 内存，重活叠加会崩溃
   - 缓解：重活串行、跑测试前停应用

### 9.2 时间风险

1. **Phase 1 是关键路径**
   - 必须 5-7 天内补齐优惠计算引擎
   - 延期会影响后续所有 Phase

2. **风控模块工期**
   - 原计划 Phase 4 需 3-4 天
   - 增加风控后调整为 5-6 天
