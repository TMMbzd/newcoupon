## 一、同步 vs 异步选择标准

### 1.1 适用场景判断

| 维度 | 同步扣减 | 异步扣减 |
|------|---------|---------|
| **并发量** | QPS < 5000 | QPS > 10000 |
| **一致性要求** | 强一致性（金融支付） | 最终一致性可接受 |
| **业务特点** | 常规领券、库存操作简单 | 秒杀场景、需要削峰填谷 |
| **技术复杂度** | 低 | 中高 |

### 1.2 判断依据

**首要因素**: 并发量  
- 超过数据库承载能力（MySQL 单表 QPS 上限约 3000-5000）必须异步

**次要因素**: 业务容忍度  
- 能接受"先返回受理号、后台异步处理"则选异步
- 必须立刻拿券则选同步

## 二、异步扣减完整架构

### 2.1 标准三层架构

```
接入层（限流）
    ↓
Redis 预扣减（原子操作）
    ↓
MQ 异步传输（削峰）
    ↓
消费端落库（本地事务）
    ↓
补偿对账（T+1）
```

### 2.2 各层技术细节

#### **Layer 1: Redis 原子预扣减**

```lua
-- Redis Lua 脚本（原子操作）
local stock_key = KEYS[1]  -- 'stock:template:12345'
local deduct_count = tonumber(ARGV[1])

local current = tonumber(redis.call('GET', stock_key) or '0')
if current >= deduct_count then
    redis.call('DECRBY', stock_key, deduct_count)
    return current - deduct_count  -- 返回剩余库存
else
    return -1  -- 库存不足
end
```

**关键点**：
- 用 `DECR/DECRBY` 原子操作，返回值 < 0 表示库存不足
- Redis 必须配置 AOF 持久化，防止宕机丢失数据

#### **Layer 2: MQ 传输**

**消息体设计**：
```json
{
  "receiptId": "RCP2026100912345678",
  "userId": 10001,
  "templateId": 12345,
  "quantity": 1,
  "requestId": "idempotent-key-xxx",
  "timestamp": 1728456789000
}
```

**可靠性保证**：
- 生产者确认（Publisher Confirm）
- 消息持久化
- 消费者手动 ACK

#### **Layer 3: 消费端落库**

```java
@RocketMQMessageListener(topic = "coupon_issuance", consumerGroup = "coupon_consumer")
public class CouponIssuanceConsumer implements RocketMQListener<CouponIssuanceMsg> {
    
    @Override
    @Transactional
    public void onMessage(CouponIssuanceMsg msg) {
        // 1. 幂等校验（防重表）
        if (isProcessed(msg.getRequestId())) {
            return; // 已处理，直接 ACK
        }
        
        // 2. 插入防重表 + 发券（同一事务）
        idempotentRepository.insert(msg.getRequestId());
        couponRepository.issueCoupon(msg.getUserId(), msg.getTemplateId());
        
        // 3. 更新受理号状态
        receiptRepository.updateStatus(msg.getReceiptId(), "SUCCESS");
        
        // 处理成功，框架自动 ACK
    }
}
```

**幂等性保证**：
```sql
CREATE TABLE idempotent_record (
  biz_id VARCHAR(64) PRIMARY KEY,  -- requestId
  status TINYINT,
  created_at DATETIME
) ENGINE=InnoDB;
```

#### **Layer 4: 补偿对账**

**T+1 对账任务**：
```sql
-- 比对 Redis 和 DB 的差异
SELECT template_id, 
       SUM(quantity) as issued_count
FROM coupon
WHERE DATE(created_at) = DATE_SUB(CURDATE(), INTERVAL 1 DAY)
GROUP BY template_id;

-- 与 Redis 中的扣减量比对
GET stock:template:{templateId}:issued_count
```

**差异处理**：
- 差异 < 阈值（如 10 张）：自动补偿
- 差异 ≥ 阈值：告警，人工介入

## 四、最终一致性保证机制

### 4.1 消息可靠投递

**四重保障**：
1. 生产者确认（Publisher Confirm）
2. 消息持久化
3. 消费者手动 ACK
4. 本地消息表补发

**RocketMQ 生产者确认示例**：
```java
SendResult result = producer.send(msg);
if (result.getSendStatus() == SendStatus.SEND_OK) {
    // 消息已成功投递到 Broker
}
```

### 4.2 幂等性保证

**方案对比**：

| 方案 | 优点 | 缺点 | 推荐度 |
|------|------|------|--------|
| 防重表（唯一索引） | 最可靠，数据库事务天然保证 | 需要额外表 | ⭐⭐⭐⭐⭐ |
| Redis 分布式锁 | 跨系统适用 | 锁超时/死锁风险 | ⭐⭐⭐ |
| RocketMQ MessageId | 自带去重 | 仅限 RocketMQ | ⭐⭐⭐⭐ |

**推荐方案: 防重表**

```java
@Transactional
public void processMessage(String requestId, ...) {
    try {
        // 插入防重表（唯一索引冲突说明已处理）
        idempotentRepository.insert(requestId);
        
        // 业务逻辑：发券
        couponRepository.issueCoupon(...);
        
        // 提交事务
    } catch (DuplicateKeyException e) {
        // 唯一索引冲突，说明已处理，直接返回
        return;
    }
}
```

### 4.3 定时对账

**对账任务设计**：
```java
@Scheduled(cron = "0 30 2 * * ?") // 每天凌晨 2:30
public void reconcile() {
    LocalDate yesterday = LocalDate.now().minusDays(1);
    
    // 1. 从 DB 汇总昨日发券量
    Map<Long, Long> dbIssuedCount = couponRepository
        .countByTemplateIdAndDate(yesterday);
    
    // 2. 从 Redis 读取扣减量
    Map<Long, Long> redisDecrCount = redisTemplate
        .opsForValue()
        .multiGet(templateIds.stream()
            .map(id -> "stock:template:" + id + ":deducted")
            .collect(Collectors.toList()));
    
    // 3. 比对差异
    for (Long templateId : templateIds) {
        Long dbCount = dbIssuedCount.getOrDefault(templateId, 0L);
        Long redisCount = redisDecrCount.getOrDefault(templateId, 0L);
        Long diff = Math.abs(dbCount - redisCount);
        
        if (diff > THRESHOLD) {
            // 差异超阈值，告警
            alertService.send("库存差异告警", 
                "模板 " + templateId + " 差异 " + diff + " 张");
        } else if (diff > 0) {
            // 小差异，自动补偿
            compensate(templateId, redisCount - dbCount);
        }
    }
}
```

## 五、消息积压与限流

### 5.1 消息积压应对

**三级策略**：

1. **扩容消费端**
   - 增加消费实例数
   - 增加消费线程数（concurrency）
   - 提高 prefetchCount（每次拉取消息数）

2. **消息优先级队列**
   - 核心商品/VIP 用户高优先级
   - 普通活动低优先级

3. **降级方案**
   - 暂停非核心活动
   - 人工介入清理无效消息

**RabbitMQ 消费者扩容配置**：
```yaml
spring:
  rabbitmq:
    listener:
      simple:
        concurrency: 10  # 最小消费线程
        max-concurrency: 20  # 最大消费线程
        prefetch: 50  # 每次拉取 50 条消息
```

### 5.2 三层限流策略

```
L1 前端限流: Nginx + 验证码
    ↓
L2 接入层限流: Sentinel/Hystrix 令牌桶
    ↓
L3 Redis 层限流: 单用户限购 + 全局限流
```

**Sentinel 限流示例**：
```java
@SentinelResource(value = "deductStock", blockHandler = "blockHandler")
public ReceiptResult receive(ReceiveRequest req) {
    // 业务逻辑
}

public ReceiptResult blockHandler(ReceiveRequest req, BlockException ex) {
    return ReceiptResult.fail("系统繁忙，请稍后重试");
}
```

**Redis 单用户限购**：
```lua
local user_key = 'user:' .. ARGV[1] .. ':template:' .. ARGV[2]
local count = redis.call('INCR', user_key)
redis.call('EXPIRE', user_key, 60)  -- 60 秒过期

if count > 5 then  -- 每分钟最多 5 次
    return -1
else
    return count
end
```

## 六、当前项目改造方案

### 6.1 保留现有同步模式

**优势**：
- 已完成 442 测试零失败
- Redis Lua + DB CAS 双防线质量高
- 适合 QPS < 5000 的常规场景

**改动**：无需改动

### 6.2 新增异步模式

**实施步骤**（Phase 1）：

#### Step 1: 接口层（1 天）
```java
// 新增 mode 参数
POST /open/v1/coupons/receive?mode=async

// 返回受理号
{
  "receiptId": "RCP2026100912345678",
  "status": "PROCESSING",
  "message": "领券申请已受理，请稍后查询结果"
}

// 查询接口
GET /open/v1/coupons/receipts/{receiptId}
{
  "receiptId": "RCP2026100912345678",
  "status": "SUCCESS",  // PROCESSING/SUCCESS/FAILED
  "couponId": 98765,
  "failReason": null
```

#### Step 2: 受理表（0.5 天）
```sql
CREATE TABLE coupon_receipt (
  receipt_id VARCHAR(64) PRIMARY KEY,
  user_id BIGINT NOT NULL,
  template_id BIGINT NOT NULL,
  status VARCHAR(16) NOT NULL,  -- PROCESSING/SUCCESS/FAILED
  coupon_id BIGINT,
  fail_reason VARCHAR(128),
  created_at DATETIME NOT NULL,
  updated_at DATETIME NOT NULL,
  INDEX idx_user (user_id, created_at)
) ENGINE=InnoDB;
```

#### Step 3: MQ 生产者（1 天）
```java
@Service
public class AsyncIssuanceService {
    
    @Autowired
    private RocketMQTemplate rocketMQTemplate;
    
    public ReceiptResult receiveAsync(ReceiveRequest req) {
        // 1. Redis 预扣减（同步模式复用）
        Long remaining = redisStockGateway.deduct(req.getTemplateId(), 1);
        if (remaining < 0) {
            return ReceiptResult.fail("库存不足");
        }
        
        // 2. 生成受理号
        String receiptId = generateReceiptId();
        receiptRepository.insert(receiptId, req, "PROCESSING");
        
        // 3. 发送 MQ 消息
        CouponIssuanceMsg msg = new CouponIssuanceMsg();
        msg.setReceiptId(receiptId);
        msg.setUserId(req.getUserId());
        msg.setTemplateId(req.getTemplateId());
        msg.setRequestId(req.getRequestId());
        
        rocketMQTemplate.syncSend("coupon_issuance", msg);
        
        // 4. 返回受理号
        return ReceiptResult.success(receiptId);
    }
}
```

#### Step 4: MQ 消费者（1.5 天）
```java
@Component
@RocketMQMessageListener(
    topic = "coupon_issuance",
    consumerGroup = "coupon_consumer"
)
public class CouponIssuanceConsumer 
    implements RocketMQListener<CouponIssuanceMsg> {
    
    @Override
    @Transactional
    public void onMessage(CouponIssuanceMsg msg) {
        try {
            // 1. 幂等校验
            if (isProcessed(msg.getRequestId())) {
                return;
            }
            
            // 2. 发券（复用同步模式逻辑）
            Long couponId = couponRepository.insert(
                msg.getUserId(), 
                msg.getTemplateId()
            );
            
            // 3. 更新受理号
            receiptRepository.updateSuccess(msg.getReceiptId(), couponId);
            
            // 4. 插入防重表
            idempotentRepository.insert(msg.getRequestId());
            
        } catch (Exception e) {
            // 失败处理
            receiptRepository.updateFailed(
                msg.getReceiptId(), 
                e.getMessage()
            );
            // 回滚 Redis（补偿）
            redisStockGateway.compensate(msg.getTemplateId(), 1);
        }
    }
}
```

#### Step 5: 测试（1 天）
- 单元测试：幂等性、失败重试
- 集成测试：MQ 消费端
- 压测：异步模式 QPS 目标 3000+
