# 架构总览与实施路线

> 本文件是工程侧的权威导航：全局架构、领域模型速览、实施路线与各阶段验收标准。
> 详细设计见各领域分册（01~09），跨分册冲突以《10-统一规范与决策对齐》为准，重大取舍见 `adr/`。

## 1. 系统定位与能力域

优惠券中台，对内支撑创/发/用/计/控五个能力域，对外通过 RPC/REST 服务上游业务方（订单/营销/客服）。

| 域 | 职责 | 关键约束 |
|---|---|---|
| 创 | 模板/批次配置、审批、预算归因 | 核心字段不可变，张数只增 |
| 发 | 领券（C端高并发）、定向发券（批量）、券码兑换 | 五重校验原子化，防超发/超领 |
| 用 | 试算、锁券、核销、释放回退 | 状态机唯一入口，占用单幂等锚点 |
| 计 | 事件事实源、统计报表、财务对账 | 事件表唯一事实源，金额分单位 |
| 控 | 风控、配额限流、监控、成本预算 | 限额四层，交叉审核 |

## 2. 全局架构（目标形态）

```
  M端(运营/财务)              C端(用户)                上游业务方
  建券/审批/报表           领券中心/券包/结算页      订单/支付/营销/风控
       │                        │                        │ 鉴权+限流+幂等号
       ▼                        ▼                        ▼
  ╔════════════ 优惠券中台（双层）═══════════════════════╗
  ║ 业务中台：玩法编排（券包/互斥/圈人），按业务隔离      ║
  ║ 技术中台：业务无关原子能力（创发用计控 + 风控下沉）    ║
  ║ 领域模型：预算→活动→模板→用户券→占用单→事件          ║
  ╚════════════════════════╪════════════════════════════╝
                           ▼
  Redis(按数据域拆集群)  MySQL(user_id 分库分表)  MQ  Leaf  ES  任务调度
```

当前实施形态（阶段 0）：单体 + 单库，见 ADR-0001。

## 3. 领域模型速览

- 实体层级：`预算 → 活动 → 券模板 → 用户券 → 占用单 → 事件`
- 模板/实例分离，实例冗余规则快照（防模板变更致历史券变性 + 分表后免 join）
- 用户券状态机（`CouponTransition`）：USABLE → LOCKED → USED（终）/ EXPIRED（终）/ INVALID（终），全部流转经状态机 + 条件 UPDATE 双层校验
- 幂等锚点：领券 = `(user_id, idempotent_key)` 唯一索引；交易 = `usage_no`（订单号+券id）
- 存储路由：user_id（表 = hash(uid)%M，库 = hash(uid)/M%N），唯一索引必须含路由因子

## 4. 实施路线与验收标准

| 阶段 | 内容 | 验收标准（不达标不进下一阶段） |
|---|---|---|
| **0 最小闭环**（当前） | 单体+单库：四表、状态机、条件更新扣库存、唯一索引幂等、占用单、过期任务表、事件表 | ① 1000 并发抢 100 张库存零超发 ② 同 requestId 重放只发一张 ③ 同取消消息重放只回退一次 |
| 1 高性能 | Redis+Lua 五重校验、二级缓存、库存分段增补（Redis≤DB 不变式） | 单批次 5000 QPS 零超发；kill -9 后库存可对平 |
| 2 规模化 | 分库分表（ShardingSphere）、outbox 异步落库开关、对账三件套、冷热归档、监控 | Redis 宕机切 DB 限流发放；对账自动发现注入的不一致 |
| 3 中台化 | biz_id 多租户、HMAC 鉴权、按上游配额限流、规则表达式、券码体系、客服工具 | 新业务接入走沙箱四类用例（签名错/重放/幂等重试/限流拒绝） |
| 4 冲刺 | 热点分桶+随机轮询+售罄跳过、全链路压测（自底向上） | 单批次 10 万 QPS、成功率 ≥99.9%、资源 1.5 倍冗余 |
