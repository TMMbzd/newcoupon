## 1. 问题与红线（v2 重申）

**问题**：当前每笔领券事务 `UPDATE coupon_template SET issued_count=issued_count+1 WHERE issued_count<total_count`——全部打同一行，~400 TPS 饱和，5000 QPS 下 DB 先死。

**红线不降级**：资损红线"**超发=0（DB 条件更新保证）**"原样保留——v1 曾想拆掉它换性能，被测试团队判定为设计缺陷（CONC-1/COMP-1/SECU-1）。v2 的答案是把这道防线**从模板行搬进桶行**：热行问题解决，防线强度不变。

## 2. 方案总图 v2（三层结构）

```
DB 层①：coupon_template（total_count / allocated——allocated 单调不减，只被开桶 CAS 推进）
DB 层②：stock_bucket 分桶账本（每桶一行：bucket_no / generation / quota / used）
         领券事务内逐笔条件扣：UPDATE stock_bucket SET used=used+1
                                WHERE template_id=? AND bucket_no=? AND generation=?
                                  AND used < quota        ← 超发红线的 DB 承重墙（热行分散到 16 行）
Redis 层：c:stk:{tpl}:{bucket}:{gen} 等四族键按（桶,世代）拆分
         c:alloc:{tpl}（DB allocated 的 Redis 镜像，开桶 Lua 原子同步更新）
         c:opening:{tpl}（开桶 single-flight 锚）
         c:fz:{tpl}（冻结牌，DEDUCT 首行短路）
```

**一笔领券的旅程（v2）**：
```
① Redis DEDUCT（路由到桶 i 当代 gen）→ stk-1, pend+1（失败/冻结/售罄在此挡下）
② DB 事务 { INSERT user_coupon + UPDATE stock_bucket used+1 WHERE used<quota }（原子）
   → affected=0：DB 侧拒绝（Redis 谎报有货，如平移攻击/残留旧桶）→ CANCEL 回滚 Redis，记 drift
③ 事务成功 → Redis CONFIRM：pend-1, dbi+1（带桶+世代寻址）
```

**改造前后对比**：
```
改造前：5000 QPS → Redis 单 key → DB UPDATE 模板行（每笔，~400 TPS 饱和）
改造后：5000 QPS → Redis 16 桶并发 → DB UPDATE 桶行（每笔但分散 16 行，单桶行 ~312 TPS < 400 饱和线）
                          ↑ 开桶 CAS 打模板行（每万笔一次）
```

## 4. 世代隔离（epoch）——治桶号复用

**键结构**：四族键带世代 `c:stk:{tpl}:{bucket}:{gen}`；`stock_bucket` 行同样带 generation。桶耗尽重开 = 同 bucket_no 新 gen（新行/新键），**不是原地重置**。

**寻址固化**：DeductCommand 固化 `(templateId, bucket, gen)`——confirm/cancel 按令牌里的世代找键，永不猜"当前代"。

**迟到操作的归属（代际口径）**：
- 迟到 **confirm**（跨重开窗口才落）→ 记入**旧代** dbi（旧代四键恒等式保持闭合）
- 迟到 **cancel(TRANSIENT)** → 记入**旧代** void（**不是 stk**——绝不让回加污染新代可卖库存，治 CONC-4/CHAO-2）
- 旧代因此成为"封账的分离账本"：identity 闭合、不参与新代买卖

**旧代 GC**：该代 pend 清零（清扫完毕）+ 分代镜像（§6.4）确认后，旧代键与 stock_bucket 旧行可归档删除；GC 前双代并存，全局等式把所有活跃代求和。

## 5. 开桶协议 v2（single-flight + 尾量 + 顺序铁律）

```
触发：DEDUCT 所有活跃代耗尽 → 返回 -10（桶耗尽，可重试语义）
编排层收到 -10：
  ① 查 c:opening:{tpl}——存在 → 别人正在开 → 短退避后重试 deduct（不打 DB）
  ② 不存在 → SET c:opening NX PX 5000（抢开桶权）
  ③ DB：UPDATE template SET allocated=allocated+N WHERE id=? AND allocated+N<=total_count
       N = min(BUCKET_SIZE, total_count-allocated)   ← 尾量语义（治 CONC-8：严格不等式在尾量时永远失败）
       affected=0 且 allocated>=total → 真售罄（走 cancel sold_out 路径）
  ④ Redis 开桶 Lua（原子）：建新代四键（bucket_total=N）+ c:alloc INCRBY N
  ⑤ DEL c:opening
崩溃夹缝（③后④前被杀）：c:alloc < DB allocated——安全方向，镜像臂补建（§6.4），重试开桶按 (bucket,gen) 幂等不重复 +N
顺序铁律：先 DB 后 Redis——窗口期偏差永远落在良性方向
```

## 6. 对账体系 v2（三条可判定等式 + 分代镜像 + 单调差分）

### 6.1 等式族（治 COMP-3：v1 层2公式自相矛盾，拆成三条各自可判定）

```
E1 分代桶内（纯 Redis 原子）：stk_{b,g}+pend_{b,g}+dbi_{b,g}+void_{b,g} ≡ bucket_total_{b,g}
E2 Redis 内部全局（纯 Redis 原子）：Σ(所有活跃代四键和) + c:alloc ≡ total_count
E3 镜像（跨系统，方向性判据，与 dbi↔ic 模式同构）：
   E3a  c:alloc ↔ DB allocated      （>：幻影分配，危险；<：补建追赶，良性）
   E3b  分代 dbi_{b,g} ↔ stock_bucket.used（同代配对，主键新鲜重读）
   E3c  全局 Σdbi ↔ SUM(stock_bucket.used)（16 行求和，廉价）；deep 权威口径 = COUNT(user_coupon)
```

### 6.2 巡检形态

层1=逐代验 E1；层2=一条 Lua 原子验 E2；镜像臂验 E3a/E3b/E3c。三步当场确认（§12 改进1）与分方向冻结（§12 改进2）不变。drift 行与告警带 `(bucket, gen)` 维度。

### 6.3 ic（issued_count）处置——冻结口径 + 消费方换锚（治 CONS-1/USAB-1）

**ic 停止逐笔维护，冻结为"迁移时点快照"**（V10 回填后不再更新，仅存档）。全部消费方换锚：

| 消费方 | v1 锚（已失效） | v2 锚 |
|---|---|---|
| 幻影臂 | dbi > 新鲜 ic | **Σdbi > SUM(stock_bucket.used)**（E3c，廉价）或分代 E3b |
| deep/REBUILD 权威口径 | ic | **COUNT(user_coupon)**（主键新鲜重读，原有 TOCTOU 防护保留） |
| T+1 日审 | ic vs COUNT | COUNT vs Σdbi+在途（分桶口径） |
| 假售罄急救"有货"判据 | ic<total | **allocated<total**（USAB-6） |
| 紧急下架/停发物理兜底 | casDeductStock 的 WHERE | **stock_bucket 桶行 WHERE used<quota 同样承载**（总监盲区①：停发维度不随模板行迁移而蒸发——OFFLINE 置 c:fz + 桶行 status） |

### 6.4 平移攻击防面（治 CONS-2/SECU-2/SECU-3）

- **资损封顶**：平移（如 stk+1/void-1 对倒）制造的虚假可卖库存，会在 DB 桶行 `used<quota` 处被拒——**钱的方向被 A 簇硬防线封死**，平移从资损降级为可用性噪音（用户收到可重试错误+drift 记录）
- **检测**：① 分代镜像 E3b/E3c（dbi↔used 配对，dbi 侧动不了）② void/dbi **单调性差分**（巡检连续两轮读数，两键只增不减——对倒必有一键倒退即报）③ E3a 防 c:alloc 被篡改铸库存（SECU-3）
- 修复权仍只属于带守卫的 REBUILD（证人不当法官）

## 7. 错误码与好用性契约（治 USAB-2/3/4）

| 码 | 语义 | 对外契约 |
|---|---|---|
| -10 | 桶耗尽（内部） | 编排层消化（开桶/换桶重试）；**绝不透出**；旧实例 default 分支兜底为可重试 DEGRADED |

## 8. V10 迁移与切流/回滚协议（治 COMP-2/CHAO-6/CONS-5）

### 8.1 V10 内容（DDL+DML+断言，一个 Flyway 脚本）

```sql
-- DDL
ALTER TABLE coupon_template ADD COLUMN allocated BIGINT NOT NULL DEFAULT 0;
CREATE TABLE stock_bucket (
  id BIGINT PK, template_id BIGINT, bucket_no INT, generation INT,
  quota BIGINT NOT NULL, used BIGINT NOT NULL DEFAULT 0,
  status TINYINT,  -- 0活跃 1封账待GC 2已归档
  uk_tpl_bucket_gen UNIQUE(template_id, bucket_no, generation)
);
-- DML 存量回填（治 COMP-2/CHAO-7：不回填=首日超发/假破缺）
UPDATE coupon_template SET allocated = issued_count;   -- 存量已发放额对齐
INSERT INTO stock_bucket(template_id, bucket_no, generation, quota, used, status)
  SELECT id, 0, 0, issued_count, issued_count, 1 FROM coupon_template WHERE issued_count > 0;
  -- 每存量模板一行"历史代"（封账），保 SUM(used)=COUNT 真值链
-- 断言（迁移失败即整体回滚）
-- SELECT COUNT(*) FROM coupon_template WHERE allocated > total_count;  必须=0
```

### 8.2 升级切流协议（治 CHAO-6：双版本双通道售卖）

```
① quiesce：全量停旧实例（graceful shutdown 30s 已配 application.yml）
② 抽干对账：跑一轮守恒巡检，旧单桶键读数与 DB 对平后置 retire（改名/标记，不删——观察一周期后清）
③ 回填校验：allocated/ic 断言 SQL 通过
④ 起新版本（桶键+世代键从此上线）
禁止：滚动发布让旧实例（打旧单桶键）与新实例（打桶键）并存——同一模板双通道售卖
```

### 8.3 回滚协议（治 CONS-5：v1 回滚本身就是超发原语）

```
① 先置 c:fz 冻结模板（止血领券）
② 回填 UPDATE coupon_template SET issued_count=(SELECT COUNT(*) FROM user_coupon WHERE template_id=?)
   ——按 DB 权威流水回填，不信任任何 Redis 读数
③ 删 stock_bucket 表数据+allocated 列，还原 Gateway 旧代码
④ 解冻，旧代码以回填后的 ic 为基线放行
```

## 9. 管理面：allocated 生命周期 + publish 最小鉴权（治 SECU-4）

- **不变量**：allocated 单调不减；只有开桶 CAS 可增；**任何发布/重发布路径不得重置**。重发布 = 对账回填（ic=COUNT、allocated=SUM(quota)）→ 再开新代桶——不是从零铸造
- **OFFLINE**：不动 allocated，置模板状态 + c:fz（停发物理兜底走桶行 WHERE+冻结双保险）
- **最小鉴权（提前到 P2b）**：TemplateController 管理端点（publish/offline/appendStock）加 X-Admin-Token 配置校验 + 操作审计行；完整 HMAC/防重放/管理面体系仍守 P7
- **重发布旧键清理协议**（治 USAB-5）：重发布先按 §8.2② 抽干 retire 旧代键，再开新代——杜绝 Σ>total 落危险方向触发假冻结

## 12. 实时性三改进（保留原文要义，与 v2 合并生效）

**改进 1：巡检三步当场确认**——失配后 (1) 主键新鲜重读 DB total（滤快照旧）→ (2) 延迟 ~200ms 第二次**独立** CONSERVATION 原子快照（滤管理窗口；同段 Lua 内读两次必然同值——脚本执行期间引擎独占，重读必须是独立 EVAL）→ (3) 仍破缺才升级。发现 120 秒→亚秒。

**改进 2：冻结 c:fz 只绑危险方向**——sum>total（超发）或 E3 镜像危险向（Σdbi>used / c:alloc>allocated）→ 三步确认后自动置位，请求被 -11 挡住；sum<total（清扫故意破缺/崩溃残留，日常发生）不冻结只走 deep 慢修。管理操作**先 DB 后 Redis**。破坏性修复（FORCE）仍走两轮确认——**分层恢复：粗动作快（冻结可逆），精修复慢（FORCE 不可逆）**。

**改进 3：假售罄当场修**——-3 且无停流牌 → 当场查 DB"有货"判据 = **allocated<total**（USAB-6 换锚）→ 开新代桶重试，用户零感知。
