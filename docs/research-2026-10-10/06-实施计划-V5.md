## 一、系统最终长什么样（目标全貌）

一句话：**一个其他企业能注册、接入、真实使用的优惠券中台**——租户在管理后台配券、发券、看账单；租户的系统通过带签名的开放接口领券、算优惠、核销；平台方运营租户、控预算、看全盘数据；所有钱相关的路径可对账、可审计、可压测出数。

| 模块 | 现状 | 目标 | 怎么变 |
|---|---|---|---|
| 租户接入（开放接口） | ✅ 已有：签名/防重放/幂等/配额/越权防线 | 补齐"接入旅程"：注册→审核→引导→对账单的完整闭环 | 小补，不推倒 |
| 券模板与规则 | 🔶 三种券类型但模型单薄 | 五维模型：类型×范围×叠加层级×互斥组×出资方；规则存库可热更 | 扩展 |
| 优惠计算（算钱） | ❌ 在途代码带伤（硬编码/回填错误） | 平台算钱：分层责任链+同层择优+分摊落行+出资拆分+配置期校验+申报防线 | 返工后重建 |
| 发放与库存 | 🔶 复杂（16 桶+世代+守恒巡检） | 受理即时返回+任务表异步落库；默认单 key 按量开桶；轻量对账（漏/重/错三分类） | 重构简化 |
| 安全 | 🔶 机器面强、人工面弱 | 六层纵深：认证（机器 HMAC+人工 Spring Security）、RBAC 授权、审计、加密脱敏、传输、业务防线 | 补全（第四步） |
| **风控** | 🔶 只有 IP 频控 | **完整版**：设备指纹（端口+本地实现）、自建人机验证、行为规则、名单库、场景/规则/因子三层引擎、决策与验证分离、命中审计与申诉 | **新建（第五步，完整模拟实现）** |
| 管理后台（前端） | ❌ 无 | 租户后台 8 页 + 平台后台 6~7 页（React 真实工程；AI 直接完成，你只体验） | 新建（第四/八步） |
| 可观测与运维 | 🔶 只有裸指标端点 | 压测七模块报告、Grafana 四大盘、CI 四门（第七步）；链路追踪、双实例、SLO 告警、备份演练（第九步） | 分两批新建 |

## 三、开工前必须讲透的三个口径

### 1. "异步"的正确切口（第 4 条要求的工程修正）

一手证据（三家公司官方复盘互证）：vivo 官方原话"领券是实时的（异步伤体验与转化率）"；字节 13 万 QPS 券系统主链路同步落库。**真正的异步在两处**：落库异步（受理即返+任务表+消息队列，vivo 官方方案，与本项目发件箱同构）与批量发券全异步。V4/V5 的做法不变：Redis 原子预扣即时受理 + 同一事务写发放任务表 + 异步落库 + 三态查询 + 同步/异步配置开关；与 vivo 生产形态的差异写成显式决策记录。

### 2. 执行节奏：两条线分开走

执行线（AI）：以环为单位不间断推进，每环末交付"代码 + 环文档包 + 提交 + 状态同步"。质量动作（全量回归/审查/先红后绿/文档）全部保留。学习线（你）：对环文档包自定节奏，学习进度不阻塞执行线。

### 3. 前端定位与环文档包

前端 = 展示与体验的载体：AI 按完整工程标准直接做出来（契约先行/类型生成/进 CI/Playwright），你只读《使用指南》（页面地图+对应后端能力+怎么点+点完数据库发生什么）。

**环文档包（每环交付的四件套）**——标准="不翻源码、不猜运行"：①变更说明（做什么/为什么/业界对标出处，只读这篇能复述设计取舍）；②可跟跑指南（命令原文+真实输出+失败看什么，复制粘贴可复现）；③完整代码走读（小段贴码+逐段讲解，读文档≈读过源码）；④自测卡（只考文档讲过的，带答案，第一题送分）。

### 第 0 步：修复地基（一切的前提）

**背景**：在途的优惠计算代码留下了一段半失败的数据库迁移脚本（执行到一半失败，迁移账本里留了失败记录，**当前工作区所有依赖数据库的测试全部起不来**），且代码里有一处会算错钱的硬编码。

| # | 工作项 | 详情 |
|---|---|---|
| 0-1 | **撤销坏迁移、恢复测试全绿** | 做什么：删掉那段迁移脚本文件（从未提交过）+ 删迁移账本里的失败记录 + 重跑全部测试取证。为什么：四个新列与券模板表第一天就有的三列（类型/面额/折扣上限）完全重复，回填语句还把"满 100 元可用"的门槛值当成"减 100 元"的面额——十倍错误。验收：既有用例全零失败的输出留档。 |
| 0-2 | **在途优惠计算代码定点返工** | 做什么（4 个严重项+一批次要项）：计算策略从券模板取类型（现在写死"满减"，满折券面额存的是基点 8500，会被当"减 85 元"报价——资损级）；补越权校验（不校验"这张券是不是你这家租户的"）；时间改成可注入（测试写死日期，过几天就会假失败）；补齐核心测试（多券择优目前零测试）。怎么做：重写测试为十条黄金用例 → 定向跑出红灯（=缺陷证据）→ 修代码 → 绿灯 → 全量回归。参考：返工清单见 [02-现状审查 §2](02-现状审查-2026-10-10.md)。验收：黄金用例全绿 + 返工清单逐项勾销 + 红灯输出留档。 |
| 0-3 | **管理面令牌过滤器的判据反转**（安全第一洞） | 做什么：鉴权过滤器目前只保护"手工列举的两个路径"，漏一个新接口就是一个无鉴权写入口。改成"**管理面非 GET 请求默认必须带令牌，显式白名单才豁免**"+ 结构性测试（遍历全部写接口断言受保护）。为什么：默认安全与默认放行是结构性差别。验收：先写结构性测试跑出红灯（证明洞存在）→ 反转后绿灯。 |

**出口证据**：全绿测试输出留档 + 一次干净提交（在途代码返工后首次入库）+ 状态同步 + **环文档包**。

### 第 5 步：风控做全（完整版，V5 升格并提前）

**为什么能"单机做全"**：本项目从第一版路线图起的外部依赖手法就是**端口 + 模拟适配器**（商品目录/画像/触达都这么做，教学文档讲过"为什么模拟不算造假"）——风控同理：**接不了的是商用服务，不是实现本身**。唯一边界：IP 画像的真实 ASN/代理库接不了（本地网段规则模拟并如实标注）；没有真实攻击者（用刷券脚本模拟，恰好就是验收方式）。

| # | 工作项 | 详情 |
|---|---|---|
| 5-1 | **名单库** | 黑/白/灰名单表 + 生效管理（时效/原因/操作人）+ 命中审计 + 申诉通道（白名单自荐）。参考：OWASP/美团风控五道防线的名单层。验收：命中名单的请求被拦且可申诉放行。 |
| 5-2 | **规则引擎三层** | 场景→规则→因子三层（多对多）；策略（识别：是否模拟器/是否新客）与**决策（处置：拒绝/限频/挑战/放行）分离**，决策可多级；因子计算"每请求只算一次、无依赖并行"。参考：美团风控官方（一手，2017）。验收：加一条规则不改代码、生效可演示。 |

## 六、工作纪律（八条）

1. 先红后绿（失败用例先写、输出留档）；2. 每环收尾四件套（提交+状态文件+工作日志+**环文档包**）；3. 设计期 3 视角审查 + 实现后对抗审查（必做）；4. 引用三重门（出处可点开+自己核过+登记）；5. 动钱先审计；6. 退役走灰度；7. **文档不交付不开下一环**；8. **文档版本化**——定稿类文档（计划/方案/调研报告/设计）修订一律出新版本文件，旧版原样留存；"当前版本"由目录总览与 STATUS 指向；活账本（STATUS/工作日志/README）按各自纪律原地更新。
