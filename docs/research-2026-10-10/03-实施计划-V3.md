> **这份计划怎么来的**：2026-10-10 用 15 个并行 agent 做了三件事——①带真实来源链接的业界调研（美团/阿里/字节/京东拼多多得物/横向难题/面试真题，6 路并行，全部标注可信度与出处）；②对项目现状的全面摸底（在途代码逐行评审 + 基础设施 + git 历史）；③三视角评审（架构/交付/面试价值）+ 完备性批评。昨日计划的九条"业界对标"论断已逐条核查（见 [02-现状审查](02-现状审查-2026-10-10.md) §3），本计划只建立在**核查通过**的证据上。
> **与 2026-10-09 六阶段计划的关系**：**取代**。保留其三个正确的大判断（优惠计算是 P0；保留改造不推倒；分阶段推进），修正其五类问题（与代码现状脱节、范围过载、工期低估、纪律条款倒退、对 ROADMAP-V2 的静默取代）。昨日计划文档不删除，作为历史记录保留并已加审计横幅。

## 0. 北极星与总原则

**北极星**：这个项目的唯一目标是「面试可防守的项目经历」。每一步的优先级 = **面试信号增量 ÷ 天数**，同时遵守「承诺 ≤ 实现」。

**总原则（六条）**：
1. **阶段出口 = 可演示证据**：每个 Phase 结束必须拿出"一条命令能跑出效果"的东西（脚本断言 / 大盘截图 / 压测一页纸），没有证据的 Phase 不算完成。
2. **纪律成本计入工期**：每个 Phase 的估算已包含全量回归（约 8 分钟/次 + 偶红排查）、先红后绿取证、多 agent 审查往返、教学文档（每阶段一篇讲解 + 刁难卡，S3 先例约 550 行）。不再出现"编码净时间"冒充总工期。
3. **引用三重门**：写进任何文档/简历的数字与文献必须 ①出处可点开 ②自己核过或跑过 ③STATUS 登记。未过门的调研结论不得进入计划与简历（昨日教训，见 02 §3）。
4. **不问"是不是标配"，问"没有它会发生什么具体的坏事"**（沿用 ROADMAP-V2 §3 判据）。
5. **多 agent 审查必做**：设计期 3 视角（可行性/风险/可测性）+ 实现后对抗审查。S2/S3 两轮审查推翻过原方案并抓出 15+ 缺陷，是本项目最有效的质检机器，不降级为"可选"。
6. **收尾三件套逐步执行**：每个实施步收尾 = git 提交 + STATUS 同步 + 工作日志追加。不允许再出现"工作区悬空 + 权威文件无记载"（已发生两次：09-27~10-01、10-09~10-10）。

## 1. 六个 Phase 总览

| Phase | 名称 | 工期* | 一句话出口（可演示证据） |
|---|---|---|---|

### P0 基线修复与事实链（1.5~2 天）——一切的前提

**背景（02-现状审查 §2 的一手证据）**：V17 迁移在 dev 库半失败（flyway_schema_history 存在 version=17 success=0 行），当前工作区**所有 @SpringBootTest 与应用启动全部瘫痪**——"442 例零红"只对 HEAD 成立，不对工作区成立。

**做什么（顺序不可乱）**：
1. **撤销整支 V17**（文件从未提交，直接删除；其 discount_type/discount_value/max_discount 与 V1 已有 coupon_type/face_value/discount_cap 完全重复，applicable_scope/scope_ids 是真新概念但必须**随接线一起落地**——schema 与读写方同一批提交，否则又是死 schema）。决策依据：02 §2 blocker-1/3。

3. **在途代码定点返工**（保留骨架、不推倒——分层与开放面纪律是对的）：
   - 引擎从券/模板取 **coupon_type**（复用领域枚举 CouponType：FULL_REDUCTION/DISCOUNT/NO_THRESHOLD，删除另造的 DiscountType），动态选策略，消除 FULL_REDUCTION 硬编码（资损级：满折券面额存的是基点 8500，会被当"减 8500 分"报价）；

   - 时间可注入（Clock/now 入参），测试不再写死 2026-10-20；
   - Checker 加 @Order 定死责任链顺序；金额计算去 double 改整数分币；INSTANT→NO_THRESHOLD 策略补齐（无门槛天然等价满减 threshold=0，可显式映射）；修 templateName/templateCode 错位与幂等 javadoc；

### P1 算钱闭环（6~8 天）⭐ 最高优先

**对标依据（全部一手/已核）**：阿里 UMP 三件套（优惠计算器 + 规则引擎 + 缓存，2016 双11 官方复盘）；淘宝"平行式满减"分层计价（单品级→店铺级→跨店级，各层门槛按单品优惠价判断）；抖音官方券规（同类互斥、跨类各一张、先券后满减）；vivo 计价中心（分层顺序计价 + 同层互斥 + 统一优惠模型，**不是** DP 全局最优——一手资料中无任何公司生产用 DP）；mall（84.9k stars）与 ruoyi-vue-pro（39.6k stars）的订单行分摊字段；美团神券平台/商家出资分摊。

**做什么**：
1. **试算完善**：互斥组内**单券择优**（多张可用券自动选最优——试算接口的自然职责，黄金用例 T4）；计算顺序固化"先券后（将来的）满减、门槛按折后金额判定"的接口位（本期只有券，但顺序语义现在就定死，对标抖音官方规则）；金额全整数分币 + 取整口径注释。
2. **适用范围**：V18 迁移给模板与券快照加 applicable_scope（ALL/CATEGORY/SKU）+ scope_ids，**同一批**接通建券写入与引擎校验；ProductCatalogPort 最小版（本地 mock 商品表 10 行种子：SKU/名称/价格/品类——显式声明是 mock 端口不是商品域，ROADMAP-V2 §4 原设计）。
3. **核销算钱（本 Phase 的灵魂，ROADMAP-V2 S4 第 3 条原文）**：ConfirmRequest 增加可选"商品行金额"；传了则**平台算钱并落 discountAmt**，不传则过渡兼容沿用旧字段（老调用方 demo.sh 不炸）；锁券时锁定金额来自试算快照。
4. **优惠分摊落行（资金侧地基）**：按行金额比例分摊 + 末行倒挤尾差 + **守恒断言 Σ分摊 = 券面额**（复用项目守恒式对账思想）；分摊明细落表（新表或扩展 usage），退款（P4）按分摊回退的依据就此落定。
5. **出资方**：券模板加 budget_owner（PLATFORM/MERCHANT，对标抖音平台券/商家券、美团商家大头/平台小头）；核销时优惠记录按出资方拆分 + 守恒断言（平台出资 + 商家出资 = 总优惠）。
6. **保底价校验（配置期校验最小版）**：试算/核销路径断言"折后价 ≥ 保底价（如原价 50%，可配）"，低于则拒绝 + 告警——S4 配置期校验的运行时切片（完整"发布时模拟叠加"随 P4 叠加规则做）。
7. **demo 扩展**：demo.sh 增加"折扣券建券→试算→核销（平台算钱）→分摊明细查询"端到端段；新增"算钱红线脚本"（错配优惠/保底价击穿必须看得见——复制 drill.sh 的断言模式到资金侧）。
8. **纪律**：设计期 3 视角审查 + 实现后对抗审查；教学文档 `study/v3/S4-优惠计算与分摊-讲解.md` + 刁难卡；简历更新（C3 算钱段解禁）。
9. **顺手债**：L23（usage 侧无 userId 的 64 表广播）随 ConfirmRequest 契约改造评估是否顺带解决。

**验收**：10 条黄金用例全绿（含义见 02 §2）；curl 多商品订单返回最优券 + 到手价 + 行级分摊；核销后 `discountAmt` 来自平台计算（DB 可查证）；出资方拆分守恒断言通过；老调用方兼容用例绿；demo/红线脚本实跑 PASS；全量零红。

### P2 预算与异步发放（5~6 天）

**对标依据**：得物"发券四闸门"（规则引擎/预算/幂等/防超发——本项目唯一缺预算一环）；阿里红包预算分桶（子预算路由 + 主预算兜底 + 回收防碎片）；S3 原设计（Redis 预扣→MQ→受理号）；美团门店日账单 T+1；京东春晚"权益验资"。

**做什么**：
1. **预算实体**：券模板/活动挂总预算 + 日预算；发券前校验、发券后扣减、超预算熔断（可配置行为：拒绝/可重试）；预算耗尽演示脚本。
2. **异步受理模式**（从旧 Phase1 移来，减载后单独立项）：受理表（receipt）+ 复用 outbox/RocketMQ/消费幂等既有链路 + 受理号查询接口；`issue_mode = sync|async` 按活动配置切换；回滚策略定死"拿不到原因→钉零+告警"（宁少卖不超发）；消息顺序性声明（文档级：本系统事件无顺序依赖 + 理由）。
3. **批量发放 + 人群包最小版**：CSV 名单导入（端口化：UserProfilePort 留位）+ 批量异步发券（复用同一 MQ 链路）+ 发放审计表；演示场景包装为"直播实时发券"（一次 API 批量 = 模拟直播间爆发，讲得出口的业务故事）。
4. **T+1 出资日账单**：XXL-JOB 出账（按租户/出资方汇总发放/核销/回退），只读查询接口——对标美团门店日账单，"计"域第一块落地。
5. **运营最小闭环**：appendStock（追加库存：DB 额度 + Redis 回补 + 清售罄牌——P2b 机制全备，L17 销账）+ 模板下线；审批维持 ADR-0005 省略（触发条件不变：第二个配券账号）。
6. **纪律与产出**：审查两轮 + 教学文档 + 刁难卡。

**验收**：预算耗尽后发券被拦（脚本可实跑）；异步模式全生命周期与同步模式结果一致 + 超发 0 + 收敛 ≤60s（用现有对账体系验证）；批量发 1000 用户成功且幂等重放只发一批；T+1 账单数字与 DB 手工核算一致；appendStock 后账目自愈（对账干净）；全量零红。

**显式不做**：触达通道/营销画布/分享裂变/口令（理由：依赖真实触达渠道，模拟价值低、面试信号弱；MessageChannelPort 留位即可）。

### P3 可观测与工程化证据（3~4 天）

**对标依据**：面试官拆简历帖点名的缺失 = 量级前置数据/控制过程/监控截图/可复现数字（调研：面试视角）；阿里"狼烟"多级缓存与 DataCheck"不一致=资损"叙事；字节 Rhino 容量闭环（容量预估→数据准备→压测验证→监控→分析→决策——借方法论不造工具）。

**做什么**：
1. **Prometheus + Grafana**：compose 加 profiles 分组（core/obs/可选 mq——顺带解决"make up 一把起 5 容器与内存纪律冲突"）；1~2 张大盘（领券链路 RT/结果分布、限流命中/熔断状态、守恒巡检、fail-open 计数——指标全部现成）；3 条核心告警规则。
2. **阶梯压测一页纸（L9 偿还口径 = 脚本阶梯，不引 JMeter/Gatling）**：单实例 → DB 桶行 → Redis 逐层加压找拐点 + 瓶颈归因 + 「并发数 = QPS × RT」自洽表 + 28 法则流量推演；**诚实标注 WSL2 单机形状验证口径**（"形状验证"话术是加分防守，不是遮羞布）。S3 的性能目标数字（同步 ≥1000 / 异步 ≥3000 QPS 下限）在此兑现：达标出数，不达标出瓶颈归因——两者都是有效交付。
3. **CI（L8 半销账）**：GitHub Actions 跑 `mvn clean test` 质量门（442 例零红从"本机手工"变"每次 push 自动产出"）；可选应用 Dockerfile（触发条件：简历要写部署能力时）。
4. **修两处环境谎言**：Makefile/README 的"make test 秒级不依赖容器"（实际需 Docker 约 8 分钟）；verify-cluster.sh 硬编码 /mnt/c Maven 路径（改为 MVN 环境变量探测 + 人话报错）。
5. **备份最小版（L20 部分）**：mysqldump 定时脚本 + 恢复演练一次。

**验收**：大盘截图（含一次故障演练的曲线回放）+ 压测一页纸（study/resume/evidence/ 归档）+ CI 绿的 commit 链接 + 演练脚本在新观测下仍 PASS。

### P4 叠加互斥与退款冲销（4~5 天）

**对标依据**：vivo 分层计价（商品级/店铺级/平台级，跨层默认叠加、同层默认互斥，"普通叠加/并行叠加"门槛基准差异）；京东 ZCube"规则=数据"（知识包热生效，解决"新增券类型要发版"）；有赞分账三字段与"核销后重算分账"；淘宝/抖音退款按分摊回退。

**做什么**：
1. **多券叠加完整版**：两层计价（券级 + 订单级）+ 叠加/互斥规则**进租户配置中心热生效**（结构化规则：互斥组 + 同组择优策略，不是表达式引擎——ZCube 最小叙事）；配置期校验完整版（发布时模拟叠加场景，低于保底价阻断/告警）。
2. **退款冲销（L24 裁决并实施）**：退款事件 → 按分摊比例冲回各方出资 → 冲销流水落表；券的处置二选一裁决（作废 vs 回可用）写 ADR；编号规范（订单/支付流水/退款单/退款批次分离）。
3. **事件可读（L11 半销账）**：核销/冲销流水查询接口（事件表从"只写不读"变可读）。
4. **纪律与产出**：审查 + 教学文档 + 刁难卡。

**验收**：混合出资的多券核销 → 部分退款全链路：各方应收应付变动 + 冲销记录可逐笔追溯 + 守恒断言通过；改一条互斥规则不重启生效（配置中心热更新演示）；全量零红。

### P5 风控最小版与收官（3~4 天）

**对标依据**：美团风控"场景/规则/因子"三层 + 决策与验证分离（2017 官方文章）；VeCDP"发放前后效果对比"（效果度量是一等公民）。

**做什么**：
1. **风控最小版（0.5~1 天）**：三因子（黑名单/频次/相似度）挂 S1 既有闸门 + 决策动作记录（拒绝/放行/限频）+ negative.sh 增加断言；**明示不做**设备指纹/人机验证（WSL 单机做不了也讲不清，文档写清边界）。
2. **统计最小版（"计"域第二块）**：发放/领取/核销/核销率只读统计接口（发放前后对比口径对标 VeCDP）；**指标口径自定义并明写**（业界无公开标准口径，符合承诺≤实现）。
3. **简历证据包整合（E1~E5 全部销账）**：压测一页纸（P3 已产出，归档整理）、面试真题映射表（美团"运营中途加库存"→开桶协议、"券已发出 DB 写失败"→补偿三变体、"Redis 扣券原子性"→Lua 五重校验，逐题"标准答法+我们怎么做+为何不同"）、GitHub README 门面（架构图 + 亮点 + 证据索引，study/ 不入库挑可公开的改写）、版本号事实核对。
4. **收官**：全量回归 + 三脚本（demo/negative/drill）+ 集群验收全 PASS 取证；STATUS 收官快照；最终教学文档。

**验收**：三类刷券脚本被拦（高频同 IP/多账号同设备特征/名单命中）实跑 PASS；统计接口数字与手工核算一致；证据包四件套（压测报告/监控截图/复盘文档/可实跑脚本）齐备归档。

## 4. 显式不做清单（每条带理由，防"静默缩水"）

| # | 不做什么 | 理由 | 触发条件（何时重新考虑） |
|---|---|---|---|
| 1 | **前端控制台（React/Vue）** | 对 Java 后端岗面试信号 ≈ 0；面试官拆简历帖点名的缺失没有一条指向"没有 UI"；演示观感由 Grafana 大盘 + 终端脚本 + XXL-JOB 自带控制台覆盖。旧计划的立项依据"React+AntD 市占率 60%"已核查为**无来源**（见 02 §3-5） | 用户明确想要可点开的管理页时：降级为 1~2 天纯 HTML+fetch 只读页（不走 React 工程链） |
| 2 | **DP/穷举求最优券组合** | 一手调研未找到任何公司生产系统用 DP 求最优券组合（vivo=分层顺序计价、淘宝=平行式满减、抖音=同类互斥跨类叠加）；做 DP 反而制造"生产为什么不用"的问穿点 | 永不（作为自学附录可写，不进代码） |
| 3 | 微服务拆分 / Nacos / Spring Cloud Alibaba | 拆分只会把守恒对账/发件箱的同机强一致变成分布式事务难题；且是付费面试项目的同质化标配叙事；与 2026-10-01 既定决策一致 | 中台稳定后按 V2 后置清单触发 |
| 4 | 清结算/轧账/账单三态/差异工单 | 属内部财务域，公开一手资料稀缺（调研结论：unverified）；做出深度必被问穿，违背承诺≤实现 | 永不（边界写进教学文档） |
| 5 | 设备指纹 / 人机验证 / 行为模型 | WSL 单机做不了也讲不清；美团一手资料也只有叙事层 | 有商用服务可接时（DeviceFingerprintPort 留位） |
| 6 | JMeter/Gatling 独立压测工具链 | 6.6G 内存纪律下收益低；脚本阶梯压测 + 诚实话术足够 | 迁移到更强机器时 |
| 7 | TLS 全站 / 依赖漏洞扫描 / 多语言 SDK / 备份演练平台化 | 产品化噪音，与面试目标无关（备份保留 mysqldump 最小版） | 简历要写运维深度时再议 |
| 8 | 触达通道 / 营销画布 / 分享裂变 / 口令 | 真实渠道依赖；玩法广度是付费面试项目的卖点而非差异点 | 有真实触达渠道时 |
