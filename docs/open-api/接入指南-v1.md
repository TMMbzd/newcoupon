# 优惠券中台 · 开放接口接入指南 v1

> 面向接入方开发者。本文档是 `v1` 的**契约**：`v1` 内只增不改——新增字段对你透明；
> 不删除字段、不改变已有字段语义。需要破坏性变更时会开 `v2`，`v1` 与 `v2` 并行运行至少一个轮换周期。
> 想先跑起来看效果：`bash scripts/open-api/demo.sh`（一条命令跑通全链路）。

---

## 1. 五分钟接入

```
① 向平台申请接入 → 拿到 appId 与 SK（Secret Key）
② 用 SK 给每个请求签名（见 §3）
③ 调接口（见 §5）；写接口要带 X-Client-Token（见 §6）
```

**SK 只会在创建与轮换时返回一次**，请立即存入密钥管理设施。查询接口不返回明文（连掩码都不返回）。

**基地址**：`https://<host>/open/v1`（本地开发：`http://localhost:8080/open/v1`）

---

## 2. 请求头总览

| 请求头 | 必填 | 说明 |
|---|---|---|
| `Authorization` | ✅ | 签名信息，见 §3 |
| `X-Client-Token` | 写接口必填 | 幂等键，见 §6 |
| `X-Timeout-Ms` | 可选 | 你的超时预算（毫秒，1~30000）。不传按 3000ms 计 |
| `Content-Type` | 写接口 | `application/json` |
| `X-Trace-Id` | 可选 | 你的链路 id。不传则由平台生成，并回写到响应头 |

---

## 3. 签名（核心）

### 3.1 待签串

7 行，用 `\n` 连接，**最后一行之后不加换行**：

```
{HTTP_METHOD}        大写，如 POST
{CanonicalPath}       路径，不含 query，不做 URL 解码（如 /open/v1/coupons/receive）
{CanonicalQuery}      query 按片段字典序排序后用 & 连接；无 query 则留空行
{BodySha256Hex}       请求体的 SHA-256（小写十六进制）；无 body 时取空串的 SHA-256
{appId}
{Timestamp}           毫秒时间戳
{Nonce}               一次性随机串，[A-Za-z0-9_-]{8,64}
```

- **CanonicalQuery**：把 query 按 `&` 切开、每片按字典序排序、再拼回去。例：`b=2&a=1` → `a=1&b=2`。
- **BodySha256Hex**：无 body 时是空串的哈希 `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855`。
- 签的是 **body 的哈希**而不是 body 本身：body 可能很大，且含换行会与分隔符歧义。

### 3.2 计算签名

```
Signature = HMAC-SHA256(SK, 待签串) 的小写十六进制
```

### 3.3 组装请求头

```
Authorization: NC-HMAC-SHA256 Credential={appId}, Timestamp={ts}, Nonce={nonce}, Signature={sig}
```

### 3.4 黄金用例（拿它验证你的实现）

| 项 | 值 |
|---|---|
| method | `POST` |
| path | `/open/v1/coupons/receive` |
| query | （无） |
| body | `{"requestId":"req-1","userId":1001,"templateId":2001}` |
| appId | `demo-app` |
| SK | `demo-secret-key` |
| timestamp | `1759280400000` |
| nonce | `abc123` |

```
bodySha256 = 8c4a865ff382d9a73dca622cd8151648183d79839b3ae132f9347caf5f618d38
canonical  = "POST\n/open/v1/coupons/receive\n\n8c4a865f...8d38\ndemo-app\n1759280400000\nabc123"
signature  = 786b25f54b296c7d79cd97b757e92ecaddc299a0576c1260b4315f9f5c4aec67
```

命令行自查（Linux/macOS）：

```bash
BODY='{"requestId":"req-1","userId":1001,"templateId":2001}'
BSHA=$(printf '%s' "$BODY" | sha256sum | cut -d' ' -f1)
printf 'POST\n/open/v1/coupons/receive\n\n%s\ndemo-app\n1759280400000\nabc123' "$BSHA" \
  | openssl dgst -sha256 -hmac 'demo-secret-key' | sed 's/^.*= //'
# 应输出 786b25f5...ec67；对不上就是拼接有差异（多半是多/少了一个换行）
```

### 3.5 时间戳与 nonce

- **时间窗 ±5 分钟**：服务端拒绝超出窗口的请求（含"未来"的时间戳）。请保证服务器时间同步（NTP）。
- **nonce 一次性**：服务端会记住用过的 nonce（保留 10 分钟），重复即拒。
  **每个请求都要用新的 nonce**——重试时也一样（但 `X-Client-Token` 要保持不变，见 §6）。
- **时间戳与 nonce 缺一不可**：前者把重放的可用期压到 5 分钟，后者管住这 5 分钟内的重放。

## 4. 响应约定

```json
{ "code": 0, "message": "成功", "data": { } }
```

- `code = 0` 表示成功；非 0 见 §7。
- **HTTP 状态码**：接入层拒绝（签名/配额/幂等/越权）使用真实 HTTP 状态（401/403/409/429/400）；
  业务失败沿用 `200 + 业务码` 的约定。**用状态码分流，用业务码定位**。

## 5. 接口清单

| 方法 | 路径 | 说明 | 幂等键 |
|---|---|---|---|
| POST | `/open/v1/templates` | 建券 | `X-Client-Token` |
| POST | `/open/v1/templates/{id}/publish` | 发布券 | `X-Client-Token` |
| GET | `/open/v1/templates/{id}` | 查券模板 | — |
| POST | `/open/v1/coupons/receive` | 领券 | `X-Client-Token` |
| POST | `/open/v1/coupons/lock` | 锁券（下单） | `X-Client-Token` |
| POST | `/open/v1/coupons/confirm` | 核销（支付成功） | `X-Client-Token` |
| POST | `/open/v1/coupons/release` | 释放（取消/超时） | `X-Client-Token` |
| GET | `/open/v1/coupons?userId=&status=` | 查券包 | — |

**数据归属**：你只能读写**自己应用**的模板与券。跨应用访问返回 `403 / 6011`。
注意 `(appId, userId)` 才是一个"逻辑用户"——不同应用传相同 `userId` 是不同的人，数据互不可见。

**用券三段的顺序**：`lock`（下单占用）→ `confirm`（支付成功）或 `release`（取消）。
`lock` 返回的 `usageNo` 是后续两步的唯一凭据，请保存好。

## 6. 幂等

写接口必须带 `X-Client-Token`（`[A-Za-z0-9_-]{8,64}`），缺失返回 `400 / 6012`。

| 场景 | 行为 |
|---|---|
| 同 token + 同参数，重复发送 | 返回**与首次逐字节相同**的响应，并带响应头 `X-Idempotent-Replay: true`。**不重复执行** |
| 同 token + 不同参数 | `409 / 6008` |
| 同 token 的上一次请求还在处理中 | `409 / 6009`，请用**同一个 token** 稍后重试 |

**什么时候用新 token**：每一次**新的业务意图**（用户点了一次领取、发起了一次下单）用一个新的 token；
**网络超时重试必须复用同一个 token**——这正是它存在的意义。

> 平台侧还有两层幂等兜底（`requestId` 防重复发券、`usageNo` 防重复核销），
> 但**契约层的幂等是你应该依赖的那一层**：它保证"重试拿到的结果与首次一致"。

## 7. 错误码与重试语义

### 7.1 接入层（6xxx，HTTP 状态码有语义）

| code | HTTP | 含义 | 可重试 | 怎么办 |
|---|---|---|---|---|
| 6001 | 401 | 签名头缺失或格式错误 | ❌ | 检查 `Authorization` 格式 |
| 6002 | 401 | 应用不存在或已停用 | ❌ | 联系平台确认应用状态 |
| 6003 | 401 | 签名不匹配 | ❌ | 按 §3.4 黄金用例自查 |
| 6004 | 401 | 时间戳超出窗口 | ❌ | 校准本机时钟（NTP） |
| 6005 | 401 | nonce 已被使用（重放） | ❌ | 每次请求用新 nonce |
| 6006 | 429 | QPS 超限 | ✅ 按 `Retry-After` 退避 | 降低频率或申请提额 |
| 6007 | 429 | 日配额用尽 | ⏳ 次日 | 联系平台提额 |
| 6008 | 409 | clientToken 重复但参数不同 | ❌ | 换新 token，或复用原参数 |
| 6009 | 409 | 同 token 请求处理中 | ✅ 短退避重试 | **用同一 token** |
| 6010 | 400 | 不支持的接口版本 | ❌ | 升级调用方 |
| 6011 | 403 | 无权访问该资源 | ❌ | 检查资源是否属于你的 appId |
| 6012 | 400 | 缺少 `X-Client-Token` | ❌ | 写接口补上该头 |

**429 一定带 `Retry-After`**（秒）。请按它退避，不要立即重试——否则限流会变成自我 DDoS。

### 7.2 业务码（HTTP 200，看 `code`）

| code | 含义 | 可重试 |
|---|---|---|
| 1000 | 参数错误（`message` 里有细节） | ❌ |
| 1001 | 重复请求（幂等命中，按成功处理） | — |
| 2001 / 2002 / 2003 | 模板不存在 / 不可领取 / 状态不允许 | ❌ |
| 3001 | 已售罄 | ❌ |
| 3002 / 3003 | 已达限领 / 已达每日上限 | ❌ |
| 4001–4006 | 券或占用单的状态冲突（详见 `message`） | ❌ |
| 5000 | 系统繁忙 | ✅ 退避重试 |
| 5001 | 系统降级中（功能临时关闭） | ✅ 退避重试 |
| 5002 | 活动暂停发放 | ✅ 退避重试 |

## 8. 限流与配额

- **维度**：按 appId。QPS 与日配额在接入时约定，超限返回 429（见 §7.1）。
- 请实现**指数退避 + 抖动**的重试；对 4xx（除 6006/6007/6009）不要重试。
- 响应头 `X-Request-Resource` 会回写本次请求归属到的资源名——排查"为什么我被限流"时有用。

---

## 9. 排查清单（签名总是不对？按顺序自查）

1. **待签串是不是 7 行？** 最后一行（nonce）后面**不能**有换行。
2. **BodySha256Hex 是不是空串的哈希？** GET 请求没有 body，但这一行**不能省**。
3. **query 排序了吗？** `?b=2&a=1` 要按 `a=1&b=2` 参与签名。
4. **时间戳是毫秒吗？** 秒级时间戳会被判超窗。
5. **HMAC 输出是小写十六进制吗？** 大写会被拒。
6. **SK 是不是轮换前的旧值？** 轮换期内容器里两把都可能有效，但过期后旧值立刻失效。
7. **路径是不是包含了 query？** `CanonicalPath` 不含 query。

最快的定位方式：**用 §3.4 的黄金用例跑一遍**——它对得上说明你的签名实现没错，问题在请求本身；
对不上就是拼接细节有差异。

## 10. 参考实现

- `scripts/open-api/lib.sh` —— bash 版签名与请求封装（可直接读、可复制到你的语言）
- `scripts/open-api/demo.sh` —— 全链路正向演示
- `scripts/open-api/negative.sh` —— 五类反例演示（签名错/超窗/重放/缺 token/越权/超配额）

```bash
# 一次完整的调用（bash + curl + openssl）
BODY='{"requestId":"r-1","userId":1001,"templateId":2001}'
TS=$(date +%s%3N); NONCE=$(head -c 12 /dev/urandom | od -An -tx1 | tr -d ' \n')
BSHA=$(printf '%s' "$BODY" | sha256sum | cut -d' ' -f1)
SIG=$(printf 'POST\n/open/v1/coupons/receive\n\n%s\n%s\n%s\n%s' "$BSHA" "$APP_ID" "$TS" "$NONCE" \
      | openssl dgst -sha256 -hmac "$APP_SECRET" | sed 's/^.*= //')

curl -X POST http://localhost:8080/open/v1/coupons/receive \
  -H "Content-Type: application/json" \
  -H "Authorization: NC-HMAC-SHA256 Credential=$APP_ID, Timestamp=$TS, Nonce=$NONCE, Signature=$SIG" \
  -H "X-Client-Token: r-1-token" \
  -d "$BODY"
```
