> 面向平台运营/前端开发/部署值班。覆盖控制台最小页（登录 + 模板列表）的形态裁定、
> 登录 CSRF 流、构建流程与部署方式。代码分支 `feat/console-min`（2026-11-05）；
> 验收测试：`ConsoleTemplateListIntegrationTest` 4 例 + 守卫回归
> （`AdminSurfaceProtectionTest` / `AdminTokenFilterTest` / `SecurityRbacIntegrationTest` /
> `OpenApiContractIntegrationTest` 共 35 例，curl 冒烟链 11 步见 §6）。
> 完整版设计：docs/research-2026-10-21/01-实施计划-V6-从券交易内核到券能力中台.md §4 2D。

## 1. 这一页是什么、不是什么（形态裁定）

**是什么**：浏览器打开 `/console/`，用 admin_user 账号登录（2A 的会话体系），看到券模板
分页列表（八列 + 上一页/下一页 + 登出）。前端是 `console/` 下的 Vite + React 18 + TS
最小工程，构建产物落在 `src/main/resources/static/console/` 由 Spring Boot 同源托管。

**不是什么**：完整版 2D（计划原文）是 AntD 5 + ProComponents + 权限菜单 + 五个页面 +
openapi-typescript 类型生成 + Playwright E2E + nginx。本刀把其中未裁定的依赖全部砍掉，
只落"登录 + 模板列表"两屏。理由逐项见 §5 裁剪登记。

**环境裁定**：本机 node v24.20.0 / npm 11.19.0 可用，按 Vite 方案实施（未走降级静态版）。

## 2. 谁在哪个路径上（认证语义总表）

| 路径 | 匿名可访问 | 判定者 |
|---|---|---|
| `GET /console/`、`/console/index.html`、`/console/assets/*` | 是（设计如此） | LegacyAdminTokenAuthenticationFilter 只保护 `/console/api/**`；HTML/JS 无敏感数据，敏感信息全在下面两行 |
| `/console/api/auth/**`（登录/登出/me） | 是 | 防线是 CSRF + 失败锁定 + 会话过期，不是管理令牌（登录自举的前提） |
| `/console/api/**`（未来的控制台数据面） | 否（401 + 7002） | 旧令牌过滤器；写操作另要 CSRF 头 |
| `GET /api/templates`（本刀新增） | 否（401 + 7002） | 旧令牌过滤器 + `@PreAuthorize("hasAuthority('template:read')")`；无角色有会话 → 403 |

守卫：`AdminSurfaceProtectionTest` 遍历全部 /api、/console 控制器映射——将来有人在
`/console/api/` 之外加数据接口（映射进 `/console` 但不受过滤器保护），测试直接红。
静态资源不走控制器，两条路不许混。

## 3. 登录 CSRF 流（页面加载到看到列表，完整时序）

前后端各记一件事：后端 CSRF 用 **Cookie 仓（httpOnly=false，JS 可读）+ X-CSRF-TOKEN
请求头回传**，且只在 `/console/api/**` 的不安全方法（POST/PUT/DELETE/PATCH）上校验——
这是 Spring Security 的 SPA 配方（SecurityConfig.spaCsrfRequestHandler）。

1. 浏览器打开 `/console/` → WebMvcConfig 把它 forward 到 `/console/index.html`
   （Boot 的 welcome page 机制只认根目录，子目录实测 404，所以显式注册）；
2. 页面 JS 先 `GET /console/api/auth/me`——两个作用：未登录返回 401+7010（前端据此
   停在登录视图），同时响应种下 `XSRF-TOKEN` Cookie（GET 不校验令牌但会发令牌）；
3. 用户提交用户名密码 → 前端读 Cookie 里的 XSRF-TOKEN，带 `X-CSRF-TOKEN` 头
   `POST /console/api/auth/login`（缺头 403）；成功 200 + 身份快照 +
   `Set-Cookie: SESSION=...`（登录时轮换过的会话 id）；
4. 之后所有请求 fetch 默认同源带 Cookie：`GET /api/templates?page=1&size=20` →
   200 列表（会话认证由过滤器链自动完成，权限每请求从 DB 重载）；
5. 登出：先再 GET 一次 /me 领新令牌（幂等），带 CSRF 头 `POST /console/api/auth/logout`
   → 会话即亡，前端回登录视图。

任何请求中途 401（会话过期/被强制下线/停用）：`console/src/api.ts` 的统一出口把视图
打回登录页并提示"会话已过期"——唯一的例外是登录接口自身的 401（那是"用户名或密码
错误/锁定"的业务答复，文案直接展示给用户）。

## 4. 构建流程（改了前端之后怎么出产物）

前置：node ≥ 18（本机 24）。npm 11 默认拦截依赖的 install 脚本，esbuild（vite 的
打包器内核）需要它下载平台二进制——首次安装后执行 `npm install-scripts approve esbuild`
（批准记录已写进 package.json 的 allowScripts，重复 clone 无需再批）。

```bash
cd console
npm install --no-fund --no-audit          # 首次/依赖变更时
npm run build                             # tsc 类型检查 + vite build
```

产物**直接**写进 `src/main/resources/static/console/`（vite.config.ts 的 outDir 直指
该目录；`emptyOutDir: true` 只清空这个子目录，不碰 static/ 其它内容）。构建产物入 git：
克隆仓库即得可运行的控制台，部署环境不需要装 node。`console/node_modules/` 不入
git（.gitignore）。

改完前端 → `npm run build` → 提交（源码 + 产物同一提交）。纯后端改动无需动 console/。

## 5. 裁剪登记（砍了什么、为什么、什么时候补）

| 砍掉的项 | 计划原文位置 | 理由 | 补的时机 |
|---|---|---|---|
| AntD 5 / ProComponents | 2D 第 1 条 | 两页用原生 table + 手写 CSS（58 行）足够；组件库引入前应先有第 3 个页面（菜单/布局） | 页面数 ≥ 3、出现表单/弹窗密集的运营界面时 |
| react-router | 2D 第 1 条 | 一共两个视图，"登录与否"就是全部路由状态，视图切换够用 | 出现第 3 个页面或需要 URL 直达时 |
| openapi-typescript 类型生成 | 2D 第 3 条 | 本刀只消费 2 个端点，api.ts 手写最小类型集；类型生成要配契约 CI 才有意义（2B 契约测试未落） | 2B 契约管线落地后一起做 |
| Playwright E2E | 2D 第 3 条 | API 契约由后端集成测试覆盖（ConsoleTemplateListIntegrationTest ④ 连"HTML 引用的 js 是否存在"都钉了）；浏览器端到端**人工冒烟**代替（步骤见 §6） | 控制台成为日常运营主入口后 |
| nginx + compose profile console | 2D 第 4 条 | 同源部署（Boot 托管静态资源）没有跨域/分流需求，多一层反代是纯运维成本 | 前后端分域部署或需要边缘缓存时 |
| 模板创建/发布、发放批次、租户、审计查询页 | 2D 第 2 条 | 本刀只裁"登录 + 模板列表"；写操作端点未开（读操作无审计），不提前铺页面 | 2D 后续刀，按 V6 计划顺序 |

## 6. 部署与人工冒烟（值班可跟跑）

部署与普通 jar 完全一致（同源，无新增外部依赖、无新迁移、无新配置键）：

```bash
docker compose up -d mysql redis        # 本地依赖
mvn spring-boot:run -Dspring-boot.run.profiles=dev
```

人工冒烟链（浏览器未自动化前的验收口径，curl 等价链 2026-11-05 实测全通）：

1. 打开 `http://<host>:8080/console/` → 应出现登录页（若 404：查 WebMvcConfig 是否
   被改动；若 401：查 LegacyAdminTokenAuthenticationFilter 的 isProtected 前缀）；
2. 错误密码登录 → 提示"用户名或密码错误"（统一文案，不区分用户名存在与否）；
3. 正确登录（admin / 环境的 SEED_ADMIN_PASSWORD 种子密码）→ 模板列表出现，
   右上角显示用户名；
4. 上一页/下一页在首页/末页呈禁用态；
5. 点登出 → 回登录页；浏览器回退再刷新 → 仍停留登录页（会话已亡）。

已知残余风险：前端交互逻辑（React 视图切换、401 拦截回登录、分页禁用态）未经真实
浏览器自动化验证——集成测试钉住的是服务端行为与静态产物存在性，浏览器端以 §6 的
人工冒烟为准。

## 7. 新端点契约速查

`GET /api/templates?page=1&size=20`（template:read；page 从 1 起缺省 1，size 缺省 20
上限 100；id 倒序；平台视角看全部，不按 app_id 过滤——内部面语义，与 /api/coupons 一致）

```json
{"code":0,"message":"成功","data":{
  "total":1,"page":1,"size":20,
  "rows":[{"id":1,"name":"满100减10","couponType":"满减","faceValue":1000,
           "publishStatus":"已发布","totalCount":6000,"issuedCount":0,
           "createTime":"2026-10-23T13:07:03"}]}}
```

非法参数：`page=0` / `size=101` → HTTP 400 + code 1000；page 超界 → 200 + 空 rows
（total 照常，前端据此算总页数）。couponType/publishStatus 直接给中文描述
（与 TemplateResponse 同口径），前端不维护码表。
